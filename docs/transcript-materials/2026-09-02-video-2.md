## Vormi paigutus ja Bootstrap `form-floating` — `0:01:48` {#vormi-paigutus}

### Selgitus

Tunni alguses täiendatakse asukoha lisamise vormi. Bootstrap annab valmis kujundusega komponendid, mistõttu ei ole vaja input-kasti, label'it ja nende olekuid nullist kujundada. Klassi `form-floating` puhul asub label algul sisendvälja sees ning liigub teksti sisestamisel üles.

Bootstrap kasutab 12-osalist ruudustikku. Klass `col-3` tähendab, et element saab rea kaheteistkümnest osast kolm. Nii saab kõrvuti paigutada linnavaliku, vormiväljad ja pildi ala.

### Skeem

```text
Bootstrap row: kokku 12 osa

┌──────────┬──────────────┬──────────┐
│ col-2    │ col-3        │ col-2    │
│ linn     │ vormiväljad  │ pilt     │
└──────────┴──────────────┴──────────┘
```

### Koodinäide

```vue
<div class="row justify-content-center">
  <div class="col col-2">
    <CitiesDropdown />
  </div>
  <div class="col col-3">
    <!-- Siia tulevad asukoha vormiväljad. -->
  </div>
  <div class="col col-2">pilt</div>
</div>
```

### Päriselu analoogia

Bootstrap grid on nagu 12 võrdse jaotusega riiul. Iga element saab kokkulepitud arvu riiulivahesid ning paigutus püsib seetõttu korrastatud.

## Sisendvälja eraldamine Vue komponendiks — `0:06:43` {#sisendvalja-komponent}

### Selgitus

Asukoha nime sisend eraldatakse faili `LocationNameInput.vue`. Väike komponent kapseldab valmis kujunduse ja sündmuse saatmise. Tunnis tehakse seda peamiselt parent–child–grandchild andmevoo harjutamiseks; õpetaja märgib, et päris projektis ei pea iga väikest HTML-lõiku tingimata omaette komponendiks tegema.

Eraldamine on kasulik siis, kui komponenti kasutatakse uuesti, sellel on iseseisev vastutus või selle peitmine muudab parent-komponendi selgemaks. Liigne eraldamine kasvatab aga failide ja ühenduskohtade arvu.

### Koodinäide (`frontend/src/components/LocationNameInput.vue`)

```vue
<script>
export default {
  name: 'LocationNameInput',
  emits: ['event-new-location-name-input'],
}
</script>

<template>
  <div class="form-floating mb-3">
    <input
      @input="$emit('event-new-location-name-input', $event.target.value)"
      type="text"
      class="form-control"
      placeholder=""
    />
    <label>Asukoha nimi</label>
  </div>
</template>
```

### Päriselu analoogia

Komponent on nagu valmis elektrikilbi moodul. Seda on mugav mujale tõsta, kuid üheainsa juhtme jaoks eraldi kilbi ehitamine ei pruugi alati ära tasuda.

## `@input`, `$event` ja väärtuse saatmine üles — `0:08:38` {#input-event}

### Selgitus

HTML-i sisseehitatud event `input` käivitub iga sisestatud tähemärgi järel. Event `change` käivitub tekstiväljal tavaliselt alles siis, kui väärtus on muutunud ja kasutaja väljast lahkub. Reaalajas vormimudeli hoidmiseks valitakse videos `@input`.

`$event` on Vue erimuutuja, mis sisaldab brauseri sündmuse objekti. Selle sees on:

- `target` — HTML-element, millel sündmus toimus;
- `target.value` — tekstivälja praegune väärtus;
- checkbox'i puhul `target.checked` — `true` või `false`.

Event'i nime saatmisest üksi ei piisa. Väärtus tuleb `$emit` teise argumendina kaasa panna; vastasel korral saab parent väärtuseks `undefined`.

### Koodinäide

```vue
<!-- Iga tähemärgi järel saadetakse uus väärtus parent'ile. -->
<input
  @input="$emit('event-new-location-name-input', $event.target.value)"
  type="text"
/>
```

```vue
<!-- Parent püüab saadetud väärtuse kinni muutujaga $event. -->
<LocationNameInput
  @event-new-location-name-input="$emit('event-new-location-name-input', $event)"
/>
```

### Skeem

```text
Kasutaja kirjutab "Tartu"
          │
          ▼
brauseri input-event
          │  $event.target.value === "Tartu"
          ▼
$emit('event-new-location-name-input', 'Tartu')
```

### Päriselu analoogia

Event'i nimi on nagu paki saateleht ja teine argument on pakk ise. Ainult saatelehe saatmisel jõuab kohale teade, kuid vajalik sisu jääb maha.

## Custom event läbi mitme komponendikihi — `0:18:22` {#event-labi-kihtide}

### Selgitus

Asukoha nime väärtus peab liikuma komponendist `LocationNameInput` läbi `LocationForm` komponendi vaatesse `LocationView`. Vue custom event ei hüppa automaatselt üle mitme kihi. Iga vahepealne parent peab sündmust kuulama ja selle vajadusel uuesti üles saatma.

Komponendi `emits` loend dokumenteerib, milliseid sündmusi komponent võib väljastada. See aitab arendustööriistal nimesid pakkuda ja kirjavigu märgata.

### Skeem

```text
LocationView                         lõplik mudel
  ▲ @event-new-location-name-input       │
  │                                      ▼
LocationForm                         location.locationName
  ▲ kuulab ja emit'ib uuesti
  │
LocationNameInput
  └─ $emit(..., $event.target.value)
```

### Koodinäide (`frontend/src/components/LocationForm.vue`)

```vue
<script>
export default {
  emits: ['event-new-location-name-input'],
}
</script>

<template>
  <LocationNameInput
    @event-new-location-name-input="
      $emit('event-new-location-name-input', $event)
    "
  />
</template>
```

Vaade salvestab lõpuks väärtuse ühisesse mudelisse:

```vue
<LocationForm
  :location="location"
  @event-new-location-name-input="location.locationName = $event"
/>
```

## Numbriväli: tekstist numbriks ja `min` piirang — `0:29:20` {#numbrivali}

### Selgitus

`NumberOfAtmsInput.vue` luuakse asukoha nime komponendi põhjal. Oluline üllatus on see, et `input type="number"` piirab küll brauseri kasutajaliidest, kuid `$event.target.value` on ikkagi string ehk tekst.

Kui backend ootab JSON-is numbrit, tuleb väärtus teisendada funktsiooniga `Number(...)`. HTML-i atribuut `min="1"` annab brauserile teadmise minimaalsest lubatud väärtusest, kuid see ei ole täielik turvagarantii: kasutaja või teine programm võib päringu koostada ilma kasutajaliideseta.

### Koodinäide (`frontend/src/components/NumberOfAtmsInput.vue`)

```vue
<input
  @input="$emit('event-new-number-of-atms-input', $event.target.value)"
  type="number"
  min="1"
  class="form-control"
/>
```

Mudeli piiril on mõistlik tekst numbriks muuta:

```vue
<LocationForm
  @event-new-number-of-atms-input="location.numberOfAtms = Number($event)"
/>
```

> Projekti praegune `LocationView.vue` omistab `$event` otse. Video põhimõtte järgi tasub `Number(...)` teisendus enne API-päringut kindlasti teha.

### Päriselu analoogia

Sildile kirjutatud „10” ja karbis olev kümme eset näevad inimese jaoks välja sama tähendusega, kuid programmile on esimene tekst ja teine arv.

## Valideerimine frontend'is, backend'is ja andmebaasis — `0:41:25` {#valideerimise-kihid}

### Selgitus

Valideerimine tähendab kontrolli, kas sisend vastab reeglitele. Videos kasutatakse näidet „ühes asukohas peab olema vähemalt üks pangaautomaat”. Seda reeglit on kasulik kaitsta kolmes kihis:

1. **Frontend** annab kasutajale kiire tagasiside ega saada teadlikult vigast päringut.
2. **Backend** ei usalda klienti ja kontrollib iga saabunud päringut.
3. **Andmebaas** hoiab viimase kaitseliinina ära vigase püsiva oleku.

Kui ärireegel muutub, tuleb omavahel kooskõlas uuendada kõiki kohti, kus sama piirang elab. Seetõttu tuleb valideerimisreeglite dubleerimisel arvestada hoolduskuluga.

### Skeem

```text
Kasutaja
   │  frontend: kiire tagasiside
   ▼
API-päring
   │  backend: autoriteetne kontroll
   ▼
Andmebaas
      viimane andmetervikluse piirang
```

### Päriselu analoogia

See meenutab lennujaama kontrolli: reisija vaatab kodus dokumendid üle, lennufirma kontrollib neid letis ja piirivalve teeb lõpliku kontrolli. Üks kontrollpunkt ei muuda teisi üleliigseks.

## Koordinaatide sisend: `split()`, massiiv ja teisendamine — `0:49:46` {#koordinaadid}

### Selgitus

Asukoha koordinaadid kopeeritakse Google Mapsist ühe tekstina, näiteks `59.437, 24.745`. Rakenduse mudelis on aga kaks eraldi numbrivälja: `lat` (latitude ehk laiuskraad) ja `lng` (longitude ehk pikkuskraad).

Meetod `split(', ')` lõikab stringi koma ja tühiku kohalt kaheelemendiliseks massiiviks. Massiivi indeksid algavad nullist. Seejärel teisendatakse mõlemad tekstid numbriks.

### Koodinäide (`frontend/src/views/LocationView.vue`)

```js
setLocationLngLat(lngLat) {
  // "59.437, 24.745" -> ["59.437", "24.745"]
  let resultArray = lngLat.split(', ')

  // Google Maps annab latitude'i esimesena.
  this.location.lat = Number(resultArray[0])
  this.location.lng = Number(resultArray[1])
},
```

### Skeem

```text
"59.437, 24.745"
        │ split(', ')
        ▼
["59.437", "24.745"]
     │            │
  Number()     Number()
     ▼            ▼
 lat: 59.437   lng: 24.745
```

See lahendus eeldab täpselt formaati „arv, tühik, arv”. Pärisrakenduses tuleks kontrollida ka elementide arvu, `Number.isFinite(...)` tulemust ja koordinaatide lubatud vahemikke.

## Transaction type'ide laadimine service-kihi kaudu — `1:20:47` {#transaction-type-service}

### Selgitus

Pangaautomaadi teenuseliigid, näiteks raha väljavõtmine või sissemakse, saadakse API-st. HTTP-päring eraldatakse `TransactionTypeService.js` faili. Nii on välise süsteemiga suhtlemine ühes kohas ja vaade kirjeldab peamiselt kasutajaliidese töövoogu.

Axios tagastab `Promise` objekti ehk lubaduse, et vastus saabub tulevikus:

- `.then(...)` käivitub eduka vastuse korral;
- `.catch(...)` käivitub vea korral;
- vastuse tegelikud andmed asuvad `response.data` väljal.

Andmed laaditakse `beforeMount()` elutsüklis, enne komponendi esmakordset ekraanile kinnitamist.

### Koodinäide (`frontend/src/services/TransactionTypeService.js`)

```js
import axios from 'axios'

export default {
  getTransactionTypesRequest() {
    return axios.get('/api/atm/transaction-types')
  },
}
```

```js
getLocationTransactionTypes() {
  TransactionTypeService.getTransactionTypesRequest()
    .then((response) => this.handleGetLocationTransactionTypesResponse(response))
    .catch(() => NavigationService.navigateToErrorView())
},

handleGetLocationTransactionTypesResponse(response) {
  this.location.transactionTypes = response.data
},

beforeMount() {
  this.getCities()
  this.getLocationTransactionTypes()
},
```

### Päriselu analoogia

Service on nagu ettevõtte postiosakond. Vaade ütleb, millist saadetist on vaja, kuid ei pea ise teadma kõiki transpordi detaile.

## Dünaamilised checkbox'id: `v-for`, `:key` ja interpolatsioon — `1:44:28` {#dunaamilised-checkboxid}

### Selgitus

Checkbox'ide arv ei ole HTML-is püsivalt ette kirjutatud. Vue loob ühe rea API-st saadud massiivi iga objekti kohta. Selleks kasutatakse direktiivi `v-for`.

`transactionType` on ühe tsükli ajutine nimi ühele objektile. `:key` annab Vuele iga rea stabiilse ja unikaalse tunnuse, mille järgi elemente muudatuste korral seostada. Tekst `{{ transactionType.transactionTypeName }}` on interpolatsioon: Vue kuvab objekti välja väärtuse, mitte sõnasõnalise teksti.

### Koodinäide (`frontend/src/components/TransactionTypesCheckbox.vue`)

```vue
<div
  v-for="transactionType in transactionTypes"
  :key="transactionType.transactionTypeId"
  class="form-check form-switch text-start"
>
  <input
    class="form-check-input"
    type="checkbox"
    role="switch"
    :checked="transactionType.isAvailable"
  />
  <label class="form-check-label">
    {{ transactionType.transactionTypeName }}
  </label>
</div>
```

### Skeem

```text
transactionTypes massiiv
  ├─ { id: 1, name: "Raha välja", isAvailable: true }
  ├─ { id: 2, name: "Raha sisse", isAvailable: false }
  └─ { id: 3, name: "Makse", isAvailable: true }
                    │ v-for
                    ▼
              kolm switch-rida
```

## Checkbox'i muudatuse pakkimine custom event'i — `2:31:42` {#checkbox-event}

### Selgitus

Ühe checkbox'i muutmisel peab parent teadma kahte asja:

1. millise teenuseliigi checkbox muutus (`transactionTypeId`);
2. milliseks selle olek muutus (`checked`).

Need väärtused pakitakse ühte objekti ja saadetakse custom event'iga üles. `@change` sobib checkbox'ile hästi, sest sündmus toimub kohe lüliti oleku muutmisel. Siin tuleb lugeda `$event.target.checked`, mitte `value`.

### Koodinäide (`frontend/src/components/TransactionTypesCheckbox.vue`)

```js
methods: {
  emitEventTransactionTypesCheckboxUpdated(transactionTypeId, checked) {
    let updatedCheckbox = {
      transactionTypeId: transactionTypeId,
      checked: checked,
    }

    this.$emit(
      'event-transaction-types-checkbox-updated',
      updatedCheckbox,
    )
  },
},
```

```vue
<input
  @change="
    emitEventTransactionTypesCheckboxUpdated(
      transactionType.transactionTypeId,
      $event.target.checked,
    )
  "
  type="checkbox"
  :checked="transactionType.isAvailable"
/>
```

`alert(JSON.stringify(updatedCheckbox))` on praeguses projektikoodis ajutine kontrollvõte. Valmis rakenduses tuleks see eemaldada.

## Õige objekti leidmine `find()` abil ja mudeli uuendamine — `2:54:29` {#find-ja-uuendamine}

### Selgitus

Vaates jõuab kohale väike uuendusobjekt. Selle `transactionTypeId` järgi tuleb massiivist leida õige teenuseliik ja muuta ainult selle `isAvailable` välja.

Massiivi meetod `find(...)` kontrollib elemente järjest ning tagastab esimese sobiva objekti. Kui vastet ei leita, on tulemus `undefined`. Seetõttu kontrollitakse enne muutmist `if (transactionType)` tingimust.

### Koodinäide (`frontend/src/views/LocationView.vue`)

```js
updateLocationTransactionTypesIsAvailableValue(updatedCheckbox) {
  const transactionType = this.location.transactionTypes.find(
    (transactionType) =>
      transactionType.transactionTypeId === updatedCheckbox.transactionTypeId,
  )

  if (transactionType) {
    transactionType.isAvailable = updatedCheckbox.checked
  }
},
```

Template seob saabunud event'i meetodiga:

```vue
<LocationForm
  @event-transaction-types-checkbox-updated="
    updateLocationTransactionTypesIsAvailableValue
  "
/>
```

### Lõplik andmevoog

```text
API
 │ GET /api/atm/transaction-types
 ▼
LocationView.location.transactionTypes
 │ props alla
 ▼
LocationForm
 │ kitsam props alla
 ▼
TransactionTypesCheckbox
 │ kasutaja muudab lülitit
 │ custom event + { id, checked } üles
 ▼
LocationForm
 │ sama event üles
 ▼
LocationView
 │ find(id)
 └─ isAvailable = checked
```

### Päriselu analoogia

See on nagu nimekirjas oleva inimese telefoninumbri muutmine: kõigepealt leitakse isik tema kordumatu ID järgi ja siis muudetakse ainult telefoninumbri lahtrit, mitte ei koostata tervet nimekirja uuesti.
