## 2. Service-kiht ja aktsiaas meetodi väljakutsumine — `0:04:03`

Projektis on kokku lepitud, et kõik backendiga suhtlemised käivad läbi eraldi **service-kihi** failide (nt `CityService.js`, `LoginService.js`). Iga selline fail ekspordib objekti, millel on meetodid konkreetsete päringute tegemiseks.

### Koodinäide

```js
// frontend/src/services/CityService.js
import axios from 'axios'

export default {
  getCitiesRequest() {
    return axios.get('/api/cities')
  },
}
```

Meetod `getCitiesRequest` **tagastab** (`return`) Axiose Promise'i. Kui `return` puuduks, jääks info meetodi sees "elama ja surema" — väljast poolt ei saaks sellele enam ligi.

### Meetodi väljakutsumine teisest failist — import

Kuna meetod elab teises failis (`CityService.js`), tuleb see fail **importida** sinna, kus seda kasutada tahetakse (nt `AtmsView.vue`):

```js
import CityService from '@/services/CityService.js'
```

Import on vajalik, sest JavaScripti fail (moodul) on vaikimisi teistele failidele "nähtamatu" — nähtavaks teeb selle alles `export`.

### Päriselu analoogia

Kujuta ette kahte eraldi tuba (faili). Ühes toas on tööriist (meetod), mida sa tahad kasutada teises toas. Selleks pead sa selle tööriista kõigepealt "sisse tooma" (importima) — sa ei saa lihtsalt öelda "kasuta seda tööriista", kui sa pole talle viidanud, kust ta tuleb.

## 3. Then/catch/finally — mida iga blokk teeb — `0:10:56`

Axiose päringul on kolm plokki: `.then()`, `.catch()` ja `.finally()`.

### Skeem

```
Server vastab -->  200/201/... (õnnestus)  --> .then() käivitub
              -->  400/500/... (viga)      --> .catch() käivitub
                                            --> .finally() käivitub IGAL JUHUL
```

### Selgitus

- **2xx** (nt 200) — päring õnnestus, `.then()` käivitub.
- **4xx** (nt 400, 403, 404) — probleem on kliendi (frontendi) poolel, nt vale päring, puuduv ressurss.
- **5xx** (nt 500) — probleem on serveri poolel, nt andmebaas kukkus, programmeerimisviga.
- `.catch()` käivitub, kui tuleb viga (tavaliselt 4xx või 5xx).
- `.finally()` käivitub **alati**, sõltumata sellest, kas õnnestus või mitte — nt spinneri peitmiseks, olenemata tulemusest.

### Koodinäide

```js
getCities() {
  CityService.getCitiesRequest()
    .then((response) => this.handleGetCitiesResponse(response))
    .catch()
    .finally()
},
```

## 4. Anonüümne funktsioon ja handle-meetod — `0:15:06`

`.then()` sisse kirjutatud `(response) => { ... }` on **anonüümne funktsioon (arrow function)**. Muutuja nimi vasakul (`response`) on ise valitud — sinna paneb Axios kogu vastuse (status, päised, andmed).

### Miks eraldi handle-meetod?

Õpetaja soovitab mitte kirjutada palju koodi otse `.then()` sulgude vahele, vaid teha eraldi nimeline **abimeetod**, mis vastust töötleb:

```js
getCities() {
  CityService.getCitiesRequest()
    .then((response) => this.handleGetCitiesResponse(response))
},

handleGetCitiesResponse(response) {
  this.cities = response.data
},
```

### Nimetamise loogika

Meetodinimede muster on **Get → Request → Response**, mis peegeldab tegelikku suhtlust:
1. `getCities` — äriloogika, mida teha tahame
2. `getCitiesRequest` — service'i meetod, mis saadab päringu (Request)
3. `handleGetCitiesResponse` — vastuse (Response) käsitlemine

Sõna `handle` on hea üldnimetus, sest tegevus ise on hägune — see "haldab" vastust, aga selle täpne sisu (millised väljad täidetakse, mida arvutatakse) on iga kord erinev.

## 5. Sildid, objektid ja mäluviited — `0:19:50`

Üks kesksemaid teemasid videos on JavaScripti (ja üldse programmeerimise) **muutuja vs. objekt** suhe.

### Selgitus

Kui kirjutada:

```js
let a = 10
let b = a
```

siis `b` ei ole "oma koopia" väärtusest 10 — mõlemad sildid (`a` ja `b`) viitavad samale kohale mälus (lihtsate väärtuste puhul on see veidi teistmoodi, aga objektide puhul on see täpselt nii — mitu silti võivad viidata **samale objektile**).

### Skeem

```
muutuja "response" (silt) ---> [mäluaadress] ---> { status: 200, data: [...], ... }
```

- **Silt** (muutuja nimi) elab ja sureb selles skoobis (meetodi sees), kus ta defineeriti.
- **Objekt**, millele silt viitab, elab mälus eraldi ja säilib, kuni miski sellele viitab.
- Kui meetodit kutsutakse välja mujalt, ei anta kaasa muutuja *nime*, vaid **mäluviite** objektile, mis selle sildi taga on.

### Miks see on tähtis?

```
Iga meetodi sisemine elu on tema enda oma.
Meetod ei tea midagi sellest, mis toimub tema väliselt — kui ta seda talle kaasa ei anta.
```

See on põhjus, miks `handleGetCitiesResponse(response)` peab saama `response`-i **parameetrina** — muidu ei oleks sellel mingit ligipääsu vastuse andmetele, kuna vastus "elab" ainult seal, kus ta tekkis (`.then()` sees).

### Päriselu analoogia

Kaks õpilast, kellel on kummalgi oma silt "õpilane" (nimi), kuid nad viitavad tegelikult samale füüsilisele inimesele — kui üks silt muudab midagi (nt "õpilane sai märkuse"), näeb ka teine silt sama muutust, sest tegelikult räägitakse ühest ja samast inimesest.

## 6. Muutuja nimetamine — mudel ja ainsus/mitmus — `0:30:57`

### Selgitus

Kui andmed on massiiv objektidest (nt linnad), siis kõige loogilisem nimi muutujale on **äriloogilise objekti nimi mitmuses**:

- `city` (üksik objekt) → `cities` (massiiv objektidest)

**Väldi** liiga spetsiifilisi nimesid nagu `cityNames` — see viitaks, et massiivis on ainult nimed, kuid tegelikult on seal terve objekt (nt `cityId` ja `cityName`).

### Koodinäide (mudel)

Objekti kuju (mudel/skeema) määratakse `data()` sees ette, ilma päris väärtusteta:

```js
data() {
  return {
    cities: [
      {
        cityId: 0,
        cityName: '',
      },
    ],
  }
},
```

See on nn "üksikobjekti mudel" — annab arendajale kohe aimu, mis kujuga andmeid oodatakse, ilma et oleks vaja neid päriselt ette kirjutada.

### JSON ja jutumärgid

Kui kopeerida vastus JSON-vormingus (Swaggerist või DevToolsist), on võtmed (keys) jutumärkides (`"cityId"`), aga JavaScripti objekti kirjaviisis need pole vajalikud (`cityId`). Neid saab kiiresti eemaldada Find & Replace'iga (Ctrl+F, Ctrl+R).

## 7. `v-for` — tsükli tegemine Vue's — `0:49:09`

Enne Vue koodi kirjutamist näitas õpetaja Java `for-each` tsükli analoogiat (video autoritest raamatunimekirjaga), et selgitada üldist mõtet: **kollektsioon paremal, üks muutuja korraga vasakul**.

### Skeem

```
v-for="city in cities"
          ↑      ↑
      ainsus   kollektsioon (massiiv, paremal)
     (üks element korraga, vasakul)
```

### Töövõte meetodi kirjutamiseks

Õpetaja soovitab õppida meelde jätma lihtsat malli:

```
? in ?
```

Vasakule tuleb ajutine muutuja (ainsus), paremale kollektsioon (mitmus).

### Koodinäide

```html
<option v-for="city in cities" :key="city.cityId" :value="city.cityId">
  {{ city.cityName }}
</option>
```

- `{{ city.cityName }}` — tavaline tekst (interpolatsioon), näitab väärtust HTML-i sees.
- `:value="city.cityId"` — atribuudi sidumine (koolon `:` ees), et öelda Vue'le "see pole tekst, vaid muutuja väärtus".

### Miks vahel `{{ }}` ja vahel `:`?

- **`{{ }}`** kasutatakse ainult tag'ide *vahel* olevas tekstis (nt `<p>{{ city.cityName }}</p>`).
- **`:atribuut="..."`** (koolon ees) kasutatakse HTML-atribuutide seadmiseks (nt `:value`, `:key`) — ilma koolonita loetakse väärtust lihtsalt tekstina (string).

## 8. `:key` atribuut ja reaktiivsus — `0:58:27`

### Selgitus

Vue on **reaktiivne raamistik** — kui andmed muutuvad, uuendab Vue automaatselt vastavat HTML-i (re-renderdab). See töötab hästi, kui objektid on lihtsad, kuid võib "eksida" (mitte märgata muutust), kui objektid on suured ja keerukad.

Selle probleemi lahendamiseks kasutatakse `:key`-atribuuti — see ütleb Vue'le, millise **unikaalse** välja järgi jälgida muutusi, selle asemel et võrrelda kogu objekti tervikuna.

### Koodinäide

```html
<option v-for="city in cities" :key="city.cityId" :value="city.cityId">
```

`city.cityId` sobib `:key`-ks, sest see tuleb andmebaasist ja on alati unikaalne — kaks linna ei saa kunagi omada sama ID-d.

### Miks see kasulik on

```
Ilma :key-ta: Vue peab vaatama iga objekti KÕIKI välju, et tuvastada muutus.
Koos :key-ga: Vue vaatab AINULT seda ühte väärtust (nt ID-d) — palju kiirem ja täpsem.
```

Modernsed arendustööriistad (nt IDE) märgivad `v-for`-i puuduva `:key` punase joonega — see on hea tava, mida alati järgida.

## 9. Komponendi ekstraktimine (Props) — `1:02:39`

### Selgitus

Kui üks osa HTML-templeidist muutub piisavalt iseseisvaks (oma loogika, oma andmed), tasub see teha **eraldi komponendiks**. Selleks kasutati IDE käsku "Extract Vue Component" (parem klõps → Refactor → Extract).

### Millal ekstraktida?

Õpetaja soovitus:

```
Enne kui lisad HTML-elemendile mingi @click või muu event'i,
mõtle, kas see peaks olema eraldi komponent.
Kui teed seda pärast (kui meetod on juba lisatud), läheb kood keerulisemaks ekstraktida.
```

### Koodinäide (props)

```js
// CitiesDropdown.vue
export default {
  name: 'CitiesDropdown',
  props: {
    cities: Array,
  },
}
```

```html
<!-- AtmsView.vue -->
<CitiesDropdown :cities="cities" />
```

`props` on viis, kuidas **vanemkomponent (parent)** annab andmeid edasi **lapsele (child)**. Andmed liiguvad ainult ühes suunas: vanemalt lapsele.

### Vue struktuurireegel

Uus komponent järgib kokkulepitud struktuuri: `<script>` üleval, `<template>` all. Failinimi kirjutatakse suure algustähega (PascalCase), nt `CitiesDropdown.vue`.

## 10. Sündmuste (Events) saatmine lapsest vanemale — `$emit` — `1:14:53`

### Selgitus

Kuna props liiguvad ainult vanemalt lapsele, on vaja teistpidist mehhanismi, kui **laps peab teavitama vanemat** millestki, mis tema sees juhtus (nt kasutaja valis rippmenüüst uue linna). Selleks kasutatakse Vue's `$emit`-i.

### Skeem

```
        Props (andmed alla)
Parent  ------------------->  Child
   ^                            |
   |  Event ($emit) (teade üles)
   +----------------------------+
```

### Nimetamise loogika

Sündmuse (event'i) nimi peab kirjeldama, **mis toimus lapses**, mitte seda, mida vanem sellega tegema peaks:

```
❌ HALB: "update-location-tables" (kirjeldab, mida VANEM peaks tegema)
✅ HEA: "event-new-city-selected" (kirjeldab, mis LAPSES toimus)
```

Kokkuleppeliselt algavad projekti oma event'id prefiksiga `event-`.

### Koodinäide

```js
// CitiesDropdown.vue
export default {
  name: 'CitiesDropdown',
  props: { cities: Array },
  emits: ['event-new-city-selected'],
}
```

```html
<select @change="$emit('event-new-city-selected', $event.target.value)">
```

`emits`-plokk on soovituslik dokumentatsioon — deklareerib, milliseid sündmusi see komponent võib saata.

### Ühe paki reegel

Kui `$emit`-iga tahetakse saata mitut väärtust korraga, tuleks need pakkida **üheks objektiks**, mitte saata mitu eraldi argumenti:

```js
// Selle asemel, et saata kaks eraldi väärtust:
$emit('event-x', value1, value2)  // ❌ ei ole tava

// Parem on pakkida üheks objektiks:
$emit('event-x', { value1, value2 })  // ✅
```

## 11. Event ja `event.target` — DOM-sündmuse info kättesaamine — `1:23:20`

### Selgitus

Kui HTML-elemendil (nt `<select>`, `<input>`) toimub sündmus (`@change`, `@click`), saab Vue automaatselt kaasa **sündmuse objekti** (`$event` / `event`). Sellel objektil on külge kinnitatud atribuut `target`, mis viitab tagasi HTML-elemendile, kus sündmus toimus.

### Koodinäide (checkbox demo)

```html
<input type="checkbox" @change="test($event.target.checked)" />
```

```js
methods: {
  test(checkedValue) {
    alert(checkedValue) // true / false
  },
}
```

### Koodinäide (select)

```html
<select @change="$emit('event-new-city-selected', $event.target.value)">
```

- `$event` — kogu sündmuse pakett.
- `.target` — HTML-element, kus sündmus toimus.
- `.value` — selle elemendi hetkeväärtus (Select'i puhul valitud `<option>`'i `value`).

Erinevatel HTML-elementidel on erinevad olulised atribuudid `target` küljes: `<input type="checkbox">` puhul on see `.checked` (true/false), `<select>` ja `<input type="text">` puhul on see `.value`.

## 12. Sündmuse kinnipüüdmine vanemas — `1:36:06`

### Selgitus

Kui laps saadab sündmuse (`$emit`), peab vanem selle **kinni püüdma**, kasutades sama nime, mida laps `$emit`-is kasutas, `@`-prefiksiga.

### Koodinäide

```html
<!-- AtmsView.vue -->
<CitiesDropdown :cities="cities" @event-new-city-selected="alertWithCityId" />
```

```js
methods: {
  alertWithCityId(cityId) {
    alert('cityId: ' + cityId)
  },
}
```

### Vormistusreegel

Kokkuleppeliselt kirjutatakse esmalt kõik props (andmed sisse), seejärel eraldi real(tel) kõik event'id (`@event-...`):

```html
<CitiesDropdown
  :cities="cities"
  @event-new-city-selected="alertWithCityId"
/>
```

## 13. Meetodi parameetrid ja `$event` — `1:41:14`

### Selgitus

Kui meetodit kutsutakse HTML-templeist otse (ilma sulgudeta, nt `@event-x="handleX"`), saadab Vue vaikimisi kaasa kogu `$emit`-iga saadetud paki **esimese argumendina**. Kui aga meetodit kutsutakse sulgudega (`@event-x="handleX($event)"`), tuleb kaasa antav sisu ise defineerida.

### Koodinäide (vaikimisi käitumine)

```html
<!-- Ilma sulgudeta: Vue paneb $emit-i väärtuse ise kaasa -->
<CitiesDropdown @event-new-city-selected="alertWithCityId" />
```

```js
alertWithCityId(cityId) {
  // cityId saabub automaatselt siia
  alert('cityId: ' + cityId)
}
```

### Koodinäide (sulgudega, käsitsi)

```html
<CitiesDropdown @event-new-city-selected="alertWithCityId($event)" />
```

Kui meetodit kutsutakse **sulgudega**, tuleb parameeter ise kaasa panna (`$event`), muidu jääb meetodi sees vastav muutuja `undefined`/`null`.

### Levinud viga

```
Kui kirjutad sulud (nagu meetodit väljakutsudes ikka tehakse),
aga unustad parameetri kaasa panna, siis meetod ei saagi vajalikku infot.
```

## 14. Git: harude ühendamine masterisse (merge) — `1:54:39`

### Selgitus

Kui arendus on tehtud, tuleb see viia projekti "master" harusse. Videos kasutati lihtsustatud lokaalset voogu (ilma pull request'ita, kuna tegu on õppeprojektiga):

```sh
git checkout master
git merge <arendusharu-nimi>
```

Git IDE küsib pärast merge'i, kas kohalik (lokaalne) haru kustutada — see on hügieen, et vältida kasutuid harusid.

### Real-world praktika

Päris töökeskkonnas tehakse **pull request** ja **code review** enne masterisse ühendamist — isegi väikeses ettevõttes, sest see jätab ajaloo (kes millal mida tegi), mida saab hiljem üle vaadata.

### Push ja tõmbamine (pull)

Kui merge tehti ainult kohalikus arvutis, ei näe teised tiimiliikmed muudatust enne, kui tehakse:

```sh
git push
```

Kui teised soovivad muudatust näha, teevad nemad omalt poolt `pull`, mis toob uuendused enda masterharusse.

## 15. FEB-10 — pangaautomaatide tabel — `2:00:19`

Video teises pooles liigutakse edasi järgmise taski (FEB-10) juurde: tuleb ehitada **pangaautomaatide asukohtade tabel**, millel on kolm veergu — **linn**, **asukoht**, **teenused**.

### Selgitus

- Tabel täidetakse automaatselt lehele maandudes (`beforeMount`), kasutades sama loogikat, mis linnade puhul.
- Teenuste veerus kuvatakse ainult need transaktsioonitüübid, mille väärtus on `true` (nt "raha sisse", "raha välja", "maksed").
- Kui `cityId` on `0` (null), tagastatakse kõik asukohad; kui `cityId` on konkreetne väärtus, tagastatakse ainult sellele linnale kuuluvad asukohad.
- Kui otsitud linnast ei leita ühtki automaati, tagastab backend erroriga vastuse (see on taotluslikult ebatavaline — tavaliselt tagastataks lihtsalt tühi massiiv).

### Päriselu analoogia

Sama loogika nagu Booking.com'is: kui otsid hotelli, mille kriteeriumitele ei vasta ükski tulemus, ei saada see üldjuhul viga tagasi, vaid lihtsalt kuvab "tulemusi ei leitud" — tühja nimekirja.

## 16. Tabeli koostamine ja CSS margin (`mb`) — `2:08:09`

### Selgitus

Tabeli struktuur ehitati Bootstrapi klasse kasutades: `table`, `table-dark`, `table-hover`. Reaalne staatiline HTML-tabel tehti kõigepealt valmis (visuaali mõttes), enne kui hakata seda dünaamiliseks muutma — see on soovituslik töövõte: **kõigepealt visuaal, siis andmed**.

### Koodinäide

```html
<table class="table table-dark table-hover">
  <thead>
    <tr>
```

## 17. Swagger, URL-i osad ja parameetrite tüübid — `2:21:05`

### Selgitus

Enne frontendi arendust tuleb backend teenus alati **testida Swaggeris/Stoplightis manuaalselt**, veendumaks, et päring toimib korrektselt (õiged andmed, õige vastus). Alles pärast seda tasub minna frontendisse.

```
Backend valmis ja testitud → siis Frontend
(vastupidises järjekorras tekivad Bad Request'id ja segadus)
```

Swagger/Stoplight ei "valeta" — see peegeldab backendi tegelikku lepingut (contract). Kui backendi arendaja lisab hiljem uue välja, mida algses dokumentatsioonis polnud, tekib "üllatus" — seepärast tasub backend enne lõpuni viia.

### URL-i osad

Video demonstreeris URL-i lahti võtmist Wordi abil, kasutades värvikoode:

```
🔴 Serveri aadress    🔵 Ressurss      🟢 Query string (?...)
https://api.example.com/atm-locations?cityId=2
```

- **Serveri aadress** — kellele sõnum läheb.
- **Ressurss (path)** — mida taga aetakse.
- **Query parameeter** (peale `?`) — lisainfo, mis läheb kaasa, aga ei otsusta, *mis* käivitatakse, vaid täpsustab, *kuidas*.

## 18. Query-parameetrid vs. raja muutujad (path variables) — `2:28:55`

### Selgitus

On kaks põhilist viisi, kuidas lisada URL-ile parameetreid:

**1. Query parameeter (request parameter):**

```
/api/atm-locations?cityId=2
```

**2. Raja muutuja (path variable):**

```
/api/location/12
```

### Erinevus

```
Query parameetrid:  JÄRJEKORD EI OLE TÄHTIS
  ?cityId=2&locationId=12  ==  ?locationId=12&cityId=2

Raja muutujad:  JÄRJEKORD ON TÄHTIS
  /location/12/city/2   ≠   /city/2/location/12
```

### Millal kumbagi kasutada?

Üldine tava (mida ka Claude Code soovitab planeerimisel):

- **Raja muutuja** — kui soovitakse konkreetset **ühte ressurssi** ID järgi (nt "anna mulle location number 12").
- **Query parameeter** — kui tegu on **filtreerimise või vähendamisega** laiema ressursihulga peal (nt "anna mulle kõik automaadid, mis kuuluvad linnale ID 2").

### Koodinäide

```
GET /api/atm-locations?cityId=2      ← filtreerimine (query parameter)
GET /api/location/12                  ← konkreetne ressurss (path variable)
```
