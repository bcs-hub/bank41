## Miks fundamentaalsed teemad on kõige tähtsamad — `0:00:10` {#fundamendid}

### Selgitus

Tunni alguses rõhutab õpetaja, et programmeerimise **põhikontseptsioonid** (muutujad, objektid, meetodid, sisend/väljund, parameetrid, argumendid, return, void) on kõige tähtsamad teadmised, mida omandada — olenemata sellest, millist programmeerimiskeelt või raamistikku hiljem kasutatakse. Need on **keelest sõltumatud** kontseptsioonid (nn "programmeerimise ABC").

Õpetaja jagab isiklikku kogemust: ta ise ei mõelnud neid asju piisavalt sügavalt läbi enne, kui hakkas ise õpetama — alles siis pidi ta endale need selgeks tegema, et teistele õpetada.

### Päriselu analoogia

Fundamentaalsete teemade õppimine on nagu maja ehitamine — kõigepealt pannakse vundament. Kui vundament on viltu, ei tule sellest hea maja välja, ükskõik kui uhke katus peale ehitatakse. Kui uue programmeerimiskeele õpid hiljem selgeks, pead õppima ainult uue **kirjaviisi (süntaksi)** — mõtted ja kontseptsioonid jäävad samaks.

## Muutuja: silt vs objekt — `0:10:05` {#muutuja-silt-objekt}

### Selgitus

Muutuja koosneb kontseptuaalselt **kolmest osast**:
1. **Tüüp** — mis tüüpi informatsiooni võib selle muutujaga siduda
2. **Nimi (silt)** — kuidas saab sellele muutujale viidata
3. **Väärtus (objekt)** — see, mis on sildi taga; **see võib muutuda**

Tähtis kontseptsioon: **silt ja objekt on kaks erinevat asja**. Silt on nagu nimesilt kaelas — see ei ole sama, mis inimene ise. Ühele objektile võib viidata mitu erinevat silti (nt kaks muutujat, mis viitavad samale õpilasele).

### Skeem

```
String firstName = "Rain";
   ^        ^          ^
 TÜÜP      SILT     OBJEKT (väärtus)

Silt "firstName" ---viitab---> Objekt "Rain" (mälus)
```

### Koodinäide (Java süntaks)

```java
String firstName;      // uue sildi loomine — tüüp määratakse AINULT SIIN
firstName = "Rain";    // väärtuse andmine sildile

System.out.println(firstName);  // silti KASUTATAKSE, tüüpi enam ei mainita
```

### Päriselu analoogia

Muutuja on nagu nimesilt konverentsil — silt (nimi) ei ole sama asi, mis inimene ise. Kui silt on kaelas, aga inimest pole (nt keegi kadus), pole seal midagi, mille poole pöörduda — see viib järgmise teema, Null Pointer Exception'i juurde.

## Konstant vs muutuja — `0:15:37` {#konstant}

### Selgitus

**Konstant** on samuti silt, aga selle **väärtus ei saa kunagi muutuda** pärast esimest omistamist. Kui üritad konstandi väärtust hiljem muuta, ütleb kompilaator (Java puhul), et kood ei vasta reeglitele ega saa bytecode'iks muutuda.

| Keel | Muutuja | Konstant |
|---|---|---|
| Java | tavaline tüüp (nt `int`, `String`) | `final` sõna tüübi ees |
| JavaScript | `let` | `const` |

### Koodinäide

```java
// Java
final double PII = 3.14;  // konstant — ei saa enam muuta
```

```javascript
// JavaScript
const pii = 3.14;   // konstant
let age = 25;        // muutuja — väärtus võib muutuda
```

## Null Pointer Exception — kui sildi taga objekti ei ole — `0:17:30` {#null-pointer}

### Selgitus

Kui programm üritab käivitada tegevust (meetodit) sildi kaudu, aga **selle sildi taga ei ole tegelikult objekti** (silt on "õhus"), tekib viga nimega **Null Pointer Exception** (lühend NPE).

Näide: kui silt `dj` peaks viitama õpetajale, aga tegelikult ei viita mitte millelegi, ja programm ütleb "dj, palun selgita mulle midagi" — see käsklus ei saa käivituda, sest sildi taga pole kedagi, kes seda teha saaks.

### Päriselu analoogia

Kujuta ette, et hõikad klassiruumis "Peeter, palun mine lülita tuli sisse", aga klassis pole kedagi nimega Peeter — käsklus lihtsalt "jääb õhku rippuma" ja midagi ei juhtu (või täpsemalt: programm annab veateate, sest ta ei tea, kuidas sellist olukorda käsitleda).

## Meetod: nimeline koodiplokk — `0:26:03` {#meetod}

### Selgitus

**Meetod on nimeline koodiplokk** — kood, mida saab ühe nime abil käivitada (välja kutsuda). Meetodite peamine eesmärk:

1. **Loetavus** — nimede abil saab koodi lugeda nagu lugu ("jaluta lüliti juurde", "vajuta lülitit"), ilma iga sammu detaili nägemata
2. **Taaskasutus** — sama koodilõiku saab käivitada mitmest kohast
3. **Organiseeritus** — pikk kood tükeldatakse loogilisteks, hallatavateks osadeks

Õpetaja rõhutab: **koodi loetavus on kompromissitu prioriteet** — kui pikem meetodi nimi aitab lugejal paremini aru saada, tuleks valida pikem nimi lühema asemel.

### Skeem

```
Enne (kõik ühes plokis):
  jaluta lüliti juurde
  vajuta lülitit
  kontrolli, kas läks põlema
  kui ei, kontrolli kaitset

Pärast (meetodiks tõstetud):
  turnOnTheLights()   <-- lihtne, loetav väljakutse
```

### Päriselu analoogia

Meetod on nagu retsepti nimi köögiraamatus. Selle asemel, et iga kord kirjutada välja "sega jahu, munad ja piim, sega korralikult läbi, lisa suhkur..." — kirjutad lihtsalt "Tee pannkoogitainas" ja igaüks, kes retsepti loeb, teab, mida see tähendab, ilma detaile nägemata (kui ta just ei taha neid vaadata).

## Klass: mall objektide loomiseks — `0:40:41` {#klass}

### Selgitus

**Klass on mall (blueprint)**, millest saab luua objekte. Kaks peamist klasside kasutuseesmärki:

1. **Andmeklassid (data classes)** — hoiavad peamiselt andmeid, vähe tegevusi. Näide: `Student` klass väljadega `firstName`, `lastName`, `age`.
2. **Tegevuste klassid** — hoiavad meetodeid (tegevusi), vähem andmeid. Näide: `EmailService` klass meetoditega `sendEmail()`, `checkInbox()`.

Kui andmebaasis on nt 100 õpilast, loob programm ühest `Student` mallist 100 objekti, igaühel oma väärtused ja oma unikaalne "mäluviide" (koht arvutimälus).

### Skeem

```
Klass Student (mall):        Objektid (loodud mallist):
  - firstName                  student1: {firstName: "Rain", lastName: "Tüür"}
  - lastName                   student2: {firstName: "Peeter", lastName: "Paan"}
  - age                        student3: {...}
```

### Päriselu analoogia

Klass on nagu küpsisevorm — vorm ise ei ole küpsis, aga sellest saab teha nii palju küpsiseid (objekte), kui tahad, kõik sama kujuga, aga igaühel oma täidis (väärtused).

## Java kompileerimine vs JavaScript tüübitundetus — `0:48:15` {#java-vs-js-tuubid}

### Selgitus

**Java on kompileeritav ja tüübikindel**:
- Kompilaator kontrollib koodi **enne käivitamist** ja keeldub kompileerimast, kui reeglitest ei peeta kinni (nt kui üritad panna numbrit `String`-tüüpi muutujasse)
- Kord määratud tüüp ei muutu

**JavaScript on interpreteeritav ja tüübitundetu**:
- Koodi ei kontrollita ette — see töötab käivitamise hetkel, "linnult"
- Sama muutuja (`let` sildiga) võib saada esmalt teksti väärtuse, seejärel numbrilise väärtuse, ilma et keegi selle vastu protesteeriks
- See annab paindlikkust ("tee, mis tahad"), aga suurendab vigade riski, kuna kompilaatori kontroll puudub

**TypeScript** on JavaScripti laiend, mis lisab tüübikindluse — tööriistad saavad kontrollida tüüpe juba koodi kirjutamise hetkel, isegi kui lõplik kood ikkagi interpreteeritakse.

### Koodinäide

```javascript
// JavaScript — tüübitundetu, see töötab probleemideta:
let value = "kümme";
value = 10;        // täiesti lubatud, tüüp muutus tekstist numbriks
```

```java
// Java — tüübikindel, see EI kompileeru:
String firstName = 10;  // VIGA: ei saa numbrit panna String-tüüpi muutujasse
```

### Päriselu analoogia

Java kompilaator on nagu range korrektor, kes loeb kogu teksti läbi enne trükkimist ja keeldub trükkimast, kui leiab grammatikavea. JavaScript on nagu vabas vormis kirjutamine ilma korrektorita — kiirem ja paindlikum, aga vead jäävad märkamata kuni need reaalselt probleeme tekitavad.

## Funktsioonid ja meetodid JavaScriptis — `1:00:31` {#funktsioonid-js}

### Selgitus

**Funktsioon** ja **meetod** on sisuliselt sama asi — nimeline koodilõik. Erinevus on ainult **süntaksis** (kirjaviisis): JavaScriptis kasutatakse sõna `function` ja terminit "funktsioon", Javas räägitakse "meetoditest". Õpetaja soovitab harjuda ütlema "meetod", et vältida hilisemat segadust, kui liigutakse Java juurde.

Funktsiooni struktuur:
```
function nimi(parameetrid) {
    // koodiplokk
}
```

**Defineerimine** (kirjeldamise loomine) ei ole sama, mis **väljakutsumine** (käivitamine) — kood funktsiooni sees käivitub alles siis, kui keegi funktsiooni nime järgi välja kutsub.

### Koodinäide

```javascript
function square(n) {      // defineerimine — luuakse "imeline koodilõik"
    return n * n;
}

square(2);                 // väljakutsumine — käivitab koodi, tagastab 4
```

## Parameetrid, sisend ja tagastusväärtus (return) — `1:03:36` {#parameetrid-return}

### Selgitus

- **Parameeter** — muutuja funktsiooni sulgude sees, mis saab väärtuse alles siis, kui funktsiooni **välja kutsutakse** koos sisendiga
- **Return** — valikuline: funktsioon võib midagi tagastada (nt arvutustulemuse) või mitte midagi tagastada (**void** — tühjus)

Töötsükkel:
1. Kõigepealt arvutatakse välja return-lause **paremal pool** olev väärtus
2. Tulemus edastatakse tagasi sinna, kust funktsiooni välja kutsuti

### Skeem

```
function square(n) {
    return n * n;    // 1. arvutatakse n * n
}                    // 2. tulemus tagastatakse väljakutsumise kohta

let result = square(2);   // result saab väärtuseks 4
```

### Päriselu analoogia

Funktsiooni väljakutsumine sisendi ja tagastusega on nagu automaat, kuhu paned raha sisse (sisend/parameeter) ja saad välja mingi toote (tagastusväärtus/return). Mõned automaadid ei anna midagi tagasi (nt annetuskast) — see vastab `void` meetoditele.

## Script tag ja HTML-i sees käivituv kood — `1:13:51` {#script-tag}

### Selgitus

JavaScript koodi saab HTML dokumenti lisada `<script>` tag'i abil. Kui brauser laeb HTML-i ja jõuab `<script>` sektsioonini, **käivitab ta kohe kogu selles sees oleva käivitatava koodi** (mitte funktsioonide defineeringuid — need alles registreeritakse, aga funktsiooni sees olev kood käivitub ainult väljakutsumisel).

### Koodinäide (projektist inspireeritud)

```html
<script>
    alert("Tere, maailm!");   // käivitub kohe, kui leht laetakse

    function addCustomer() {   // ainult defineeritud, ei käivitu veel
        console.log("Add customer meetod algab");
    }
</script>
```

Nupu klikk seotakse funktsiooniga `onclick` atribuudi kaudu:

```html
<button onclick="addCustomer()">Lisa uus klient</button>
```

## DOM ja document.getElementById() — `1:33:13` {#dom}

### Selgitus

**DOM** (Document Object Model) on tehnoloogia, mis lubab JavaScripti koodil "katsuda" ja muuta HTML elemente. Õpetaja kasutab metafoori **"väike Tom"** — keegi, kellel on ligipääs kogu lehele ja kes saab elemente üles otsida ja nendega toimetada.

`document.getElementById(id)` on meetod, mis:
- Ootab sisse **stringi** (elemendi ID-d)
- Tagastab **HTML elemendi objekti** (või `null`, kui elementi ei leitud)

Elemendi väärtuse (nt input-kasti sisu) kättesaamiseks kasutatakse `.value` atribuuti.

### Koodinäide (projektist, `frontend/index.html` kontekstis)

```javascript
function addCustomer() {
    let firstName = document.getElementById('firstName').value
    let lastName = document.getElementById('lastName').value
    let age = document.getElementById('age').value

    alert("Süstemi lisati: " + firstName)
}
```

### Päriselu analoogia

`document.getElementById()` on nagu ID-kaardi kontroll — annad ID numbri ja saad tagasi täpselt selle inimese (elemendi), keda otsisid. Kui sellise ID-ga inimest pole, ei saa sa midagi tagasi (`null`).

## "Meetodi palve" — miks tagastusväärtus tuleb muutujasse panna — `1:46:55` {#meetodi-palve}

### Selgitus

See on üks tähtsamaid algajate jaoks raskeid kontseptsioone: kui kutsud välja meetodi, mis midagi tagastab, ja soovid selle infoga hiljem edasi toimetada, **pead selle tulemuse siduma muutujaga (sildiga)**. Vastasel juhul pole sul mitte millelegi viidata — tulemus "kaob".

Õpetaja nimetab seda **"meetodi palveks"** — korduv juhend, mida ta oma õpilastele meelde tuletab, kuni see harjumuseks muutub.

### Koodinäide

```javascript
// VALESTI — tulemus ei ole millegagi seotud, ei saa seda edasi kasutada:
document.getElementById('firstName');

// ÕIGESTI — tulemus on seotud sildiga, saab edasi kasutada:
let firstNameElement = document.getElementById('firstName');
alert(firstNameElement.value);

// Lühem variant (ahelatuna):
let firstNameValue = document.getElementById('firstName').value;
```

### Päriselu analoogia

Kui küsid kelleltki "too mulle see pastakas" ja keegi selle toob, aga sa ei võta seda vastu (ei pane "muutujasse"), siis pastakas jääb lihtsalt seisma õhus — sul pole enam midagi, millega edasi tegutseda. Pead vastu võtma (sildistama) selle, mida sulle antakse.

## Objektid: Old School loomine vs objekti literaal — `2:13:43` {#objektid}

### Selgitus

Objekti loomiseks JavaScriptis on kaks viisi:

**1. Vana stiil (Old School)** — luuakse tühi objekt ja väljad lisatakse hiljem eraldi:

```javascript
let customerV1 = new Object();   // tühi objekt
customerV1.firstName = "Rain";   // väli lisatakse hiljem
customerV1.lastName = "Tüür";
```

**2. Objekti literaal** (kaasaegne, soovitatud viis) — objekt luuakse kohe koos väärtustega:

```javascript
let customerV2 = {
    firstName: firstName,   // võti: väärtus (muutujast)
    lastName: lastName,
    age: age
};
```

Objekti literaalis kasutatakse `koolon`-it (`:`), mitte võrdusmärki, ning väljad eraldatakse komadega.

### Skeem

```
Old School:                    Objekti literaal:
new Object()  --> tühi          { firstName: "Rain",
  .firstName = "Rain"             lastName: "Tüür" }
  .lastName = "Tüür"              (kõik korraga, ühe reaga)
```

### Päriselu analoogia

Objekti literaal on nagu tühja ankeedi kohe täidetult esitamine — versus vana viis, kus esmalt annad tühja lehe ja siis lisad iga välja eraldi sammuna. Sama tulemus, aga literaal on kiirem ja kompaktsem.

## JSON.stringify() — objektist tekstiks — `2:26:55` {#json}

### Selgitus

**JSON** (JavaScript Object Notation) on kirjaviis, mis teisendab JavaScripti objekti **tekstiks (stringiks)**, et seda saaks süsteemide vahel (nt frontend ja backend) saata. See on inimloetav ja masinloetav formaat.

`JSON.stringify(objekt)` — meetod, mis teeb ükskõik millisest JavaScripti objektist teksti kujul versiooni.

Ainuke reaalne erinevus JSON-i ja JavaScripti objekti literaali vahel: **JSON-is peavad võtmed (keys) olema jutumärkides**, JavaScriptis mitte tingimata.

### Koodinäide (projektist, `frontend/index.html`)

```javascript
let customerV2 = {
    firstName: firstName,
    lastName: lastName,
    age: age
}

alert("Süstemi lisati: " + JSON.stringify(customerV2))
```

```json
{
    "firstName": "Rain",
    "lastName": "Tüür",
    "age": "25"
}
```

### Päriselu analoogia

JSON on nagu universaalne kirjablankett, mida mõistavad kõik osapooled — nagu HTML tag'id, mida brauser mõistab, mõistab iga programmeerimiskeel JSON formaati, mis teeb sellest ideaalse "ühise keele" andmete edastamiseks süsteemide vahel.
