## `ImageInput` komponendi kasutuselevõtt — `0:02:33` {#image-input}

### Selgitus

Asukoha vormil olid juba linn, asukoha nimi, automaatide arv, koordinaadid ja teenuseliigid. Järgmisena lisatakse `ImageInput` komponent, et kasutaja saaks valida pangaautomaadi asukoha pildi.

`input type="file"` avab brauseri failivaliku. Atribuut `accept` piirab dialoogis nähtavaid failitüüpe, kuid backend peab faili tüüpi siiski ise kontrollima, sest frontend'i piirangust saab mööda minna.

### Koodinäide (`frontend/src/components/image/ImageInput.vue`)

```vue
<input
  ref="fileInput"
  class="form-control"
  type="file"
  @change="handleImage($event)"
  accept="image/x-png,image/jpeg,image/gif"
/>
```

Komponent registreeritakse vormis:

```js
import ImageInput from '@/components/image/ImageInput.vue'

export default {
  components: { ImageInput },
}
```

### Päriselu analoogia

Failisisend on nagu dokumendi vastuvõtuluuk: kasutaja valib, mida luugist sisse anda, kuid vastuvõtja peab ikkagi kontrollima, kas saabus lubatud dokument.

## Faili valimine ja `FileReader` — `0:24:21` {#file-reader}

### Selgitus

Faili valimisel tekib brauseri `change` event. Valitud failid asuvad `$event.target.files` kogumis. Videos kasutatakse esimest faili ehk indeksit `0`, sest sisend lubab valida ühe pildi.

`FileReader` on brauseri sisseehitatud tööriist kohaliku faili sisu lugemiseks. Lugemine on asünkroonne: tulemus ei ole kohe olemas, vaid saabub hiljem `onload` funktsiooni kaudu.

### Koodinäide

```js
handleImage(event) {
  // files[0] on kasutaja valitud esimene fail.
  const selectedImage = event.target.files[0]
  this.emitBase64(selectedImage)
},

emitBase64(fileObject) {
  const reader = new FileReader()

  reader.onload = () => {
    const imageDataBase64 = reader.result
    this.$emit('event-new-image-selected', imageDataBase64)
  }

  reader.onerror = (error) => {
    alert(error)
  }

  reader.readAsDataURL(fileObject)
},
```

### Skeem

```text
Kasutaja valib faili
        │
        ▼
event.target.files[0]
        │
        ▼
FileReader.readAsDataURL(file)
        │ asünkroonne lugemine
        ▼
reader.onload → reader.result
```

## Pilt kui Base64-andmed — `0:33:30` {#base64}

### Selgitus

Arvuti jaoks on pilt andmed ehk baidid. `readAsDataURL()` teisendab need Data URL-iks, milles faili sisu on Base64-kujul tekstina. Tulemus algab tavaliselt metaandmetega, näiteks:

```text
data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...
```

Data URL-i saab panna otse `<img>` elemendi `src` atribuuti. See on väikeste piltide ja eelvaadete puhul mugav, kuid Base64 kasvatab andmemahtu ning väga suuri pilte ei tasu mõtlematult JSON-sõnumisse või andmebaasi panna.

### Koodinäide

```js
reader.onload = () => {
  // reader.result sisaldab nii MIME-tüüpi kui ka Base64 sisu.
  const imageDataBase64 = reader.result
  this.$emit('event-new-image-selected', imageDataBase64)
}
```

### Päriselu analoogia

Base64 on nagu pildi ümberkirjutamine piiratud tähestikuga väga pikaks tekstiks. Sisu säilib, kuid kirjeldus võtab rohkem ruumi kui algne fail.

## Pildi andmete saatmine läbi komponendikihtide — `0:42:15` {#pildi-event}

### Selgitus

Pildiandmete omanik on `LocationView`, sest seal asub terviklik `location` objekt. `ImageInput` ei muuda seda objekti otse. Ta saadab event'i, `LocationForm` vahendab selle edasi ning `LocationView` salvestab saadud väärtuse väljale `location.imageData`.

### Skeem

```text
ImageInput
  │ event-new-image-selected + Base64
  ▼
LocationForm
  │ sama event ja sama pakk edasi
  ▼
LocationView
  └─ location.imageData = $event
```

### Koodinäide (`frontend/src/components/LocationForm.vue`)

```vue
<ImageInput
  @event-new-image-selected="
    $emit('event-new-image-selected', $event)
  "
/>
```

```js
emits: [
  'event-new-image-selected',
],
```

Lõplik vastuvõtja:

```vue
<LocationForm
  :location="location"
  @event-new-image-selected="location.imageData = $event"
/>
```

## Vaikimisi pilt ja kasutaja valitud eelvaade — `0:47:47` {#pildi-eelvaade}

### Selgitus

Pilt on vormil valikuline. Kui kasutaja pole faili valinud, kuvatakse projektiga kaasas olev vaikimisi pilt `frontend/src/assets/images/atm.png`. Kui `location.imageData` sisaldab Base64 Data URL-i, kuvatakse kasutaja valitud pilt.

HTML-i `<img>` element näitab `src` aadressil olevat pilti. Bootstrap klass `img-thumbnail` lisab sobiva suuruse ja äärisega eelvaate kujunduse.

### Koodinäide (`frontend/src/components/LocationForm.vue`)

```vue
<img
  src="@/assets/images/atm.png"
  class="img-thumbnail"
  alt="pangaautomaadi pilt"
/>
```

`alt` kirjeldab pilti ekraanilugejale ning kuvatakse ka juhul, kui pilti ei õnnestu laadida.

### Päriselu analoogia

Vaikimisi pilt on nagu profiilipildi hall siluett: kasutajaliides ei jää tühjaks, kuid kasutaja valik asendab selle kohe päris pildiga.

## `v-if` ja `v-else`: kuva sõltub andmetest — `1:01:48` {#tingimuslik-kuvamine}

### Selgitus

Vue tingimuslik renderdamine tähendab, et DOM-i lisatakse ainult tingimusele vastav element. `v-if` kontrollib, kas `imageData` on tühi string. Kohe järgneva elemendi `v-else` haru kehtib kõigil muudel juhtudel.

### Koodinäide

```vue
<!-- Pilti pole valitud: kuva projekti vaikimisi pilt. -->
<img
  v-if="location.imageData === ''"
  src="@/assets/images/atm.png"
  class="img-thumbnail"
  alt="pangaautomaadi pilt"
/>

<!-- Pilt on valitud: src tuleb muutujast, seega on vaja koolonit. -->
<img
  v-else
  :src="location.imageData"
  class="img-thumbnail"
  alt="pangaautomaadi pilt"
/>
```

Koolon `:src` on lühend kujust `v-bind:src`. Ilma koolonita arvaks brauser, et `location.imageData` on sõnasõnaline URL.

### Skeem

```text
Kas location.imageData === ''?
        ├─ jah  → assets/images/atm.png
        └─ ei   → kasutaja Base64-pilt
```

## Failivaliku kustutamine `ref` abil — `1:06:32` {#file-input-ref}

### Selgitus

Failisisend on erandlik HTML-element: selle nähtavat väärtust ei saa tavapärase Vue andmevooga täielikult juhtida. Valitud failinime tühjendamiseks kasutatakse template reference'it ehk `ref` viidet.

`ref="fileInput"` annab komponendi JavaScriptile juurdepääsu konkreetsele DOM-elemendile läbi `this.$refs.fileInput`. Otsest DOM-i muutmist tasub Vue's üldiselt vältida, kuid file input'i puhastamine on põhjendatud erand.

### Koodinäide (`frontend/src/components/image/ImageInput.vue`)

```vue
<input ref="fileInput" type="file" />
```

```js
clearFileInput() {
  // Kaitsekontroll: element peab olema renderdatud ja olemas.
  if (this.$refs.fileInput) {
    this.$refs.fileInput.value = ''
    this.$emit('event-chosen-image-cleared')
  }
},
```

### Päriselu analoogia

Tavaliselt juhib Vue ekraani nagu keskne juhtpult. `ref` on hooldusluuk, mille kaudu puudutatakse vajadusel ühte konkreetset seadet otse.

## Kustutamise event ja mudeli sünkroniseerimine — `1:23:39` {#pildi-kustutamise-event}

### Selgitus

Failinime eemaldamine sisendilt muudab ainult visuaalset HTML-elementi. `location.imageData` jääks ilma lisakoodita endiselt Base64-pilti hoidma. Visuaalne olek ja rakenduse andmed tuleb teadlikult sünkroniseerida.

Kustutamisnupp saadab event'i `event-chosen-image-cleared`. Sellega ei ole vaja pakki kaasa saata, sest sündmus ise ütleb kõik vajaliku: pildiväli tuleb taastada tühjaks stringiks.

### Koodinäide

```vue
<!-- ImageInput -->
<button type="button" @click="clearFileInput">
  <PhTrash :size="32" />
</button>
```

```vue
<!-- LocationForm vahendab teate edasi. -->
<ImageInput
  @event-chosen-image-cleared="
    $emit('event-chosen-image-cleared')
  "
/>
```

```vue
<!-- LocationView taastab keskse mudeli algseisu. -->
<LocationForm
  @event-chosen-image-cleared="location.imageData = ''"
/>
```

Kui mudel muutub tühjaks, lülitab `v-if` eelvaate automaatselt tagasi vaikimisi pildile.

## `LocationService`: asukoha POST-päring — `1:38:48` {#location-post-service}

### Selgitus

HTTP `POST` meetodit kasutatakse uue ressursi loomiseks. Axios `post` võtab siin kaks olulist argumenti:

1. URL, kuhu päring saadetakse;
2. request body ehk objekt, mis saadetakse JSON-andmetena kaasa.

API kirjeldus on leping ehk contract: välja nimed, tüübid ja struktuur peavad vastama backend'i oodatud kujule. Näiteks arv peab JSON-is olema arv, mitte jutumärkides tekst.

### Koodinäide (`frontend/src/services/LocationService.js`)

```js
postAtmLocationRequest(location) {
  // TODO: päris backendiga minnakse URL-is ainsuse kujule.
  return axios.post('/api/atm/locations', location)
},
```

Saadetava objekti üldkuju:

```js
location: {
  cityId: 2,
  locationName: 'Mustamäe keskus',
  numberOfAtms: 2,
  imageData: '',
  lat: 59.4,
  lng: 24.7,
  transactionTypes: [
    { transactionTypeId: 1, transactionTypeName: 'Raha välja', isAvailable: true },
  ],
}
```

## Tehnilise ja äriloogilise meetodi eristamine — `1:55:23` {#meetodite-vastutus}

### Selgitus

Service-kihi meetod `postAtmLocationRequest` kirjeldab tehnilist tegevust: millise HTTP-meetodiga millisele ressursile päring saadetakse. Vaate meetod `addLocation` kirjeldab kasutaja eesmärki: lisa asukoht.

Selline nimede ja vastutuse jaotus laseb koodi lugeda eri detailsuse tasemetel:

```text
LocationView              → millist kasutaja töövoogu täidetakse?
  addLocation()           → lisa asukoht
    validate...()         → kas sisend sobib?
    LocationService       → kuidas sõnum tehniliselt saadetakse?
      postAtmLocationRequest(location)
```

### Koodinäide

```js
// Vaates: äriloogiline tegevus.
addLocation() {
  // 1. Lähtesta vana viga.
  // 2. Kontrolli vormi.
  // 3. Kui kõik sobib, kutsu service välja.
}
```

```js
// Service'is: tehniline HTTP-operatsioon.
postAtmLocationRequest(location) {
  return axios.post('/api/atm/locations', location)
}
```

### Päriselu analoogia

„Saada pakk” on äriline eesmärk. „Tee POST-päring aadressile `/api/atm/locations`” on tehniline teostusviis. Kasutaja töövoog ei pea kõiki transpordi detaile oma nimes kandma.

## Vorminõuded ja frontend–backend vastutus — `2:01:25` {#vorminouded}

### Selgitus

Enne saatmist tuleb kontrollida kohustuslikke välju. Videos nimetatakse vähemalt järgmisi reegleid:

- linn peab olema valitud;
- asukoha nimi peab olema sisestatud;
- automaatide arv peab vastama nõuetele;
- vähemalt ühe transaction type'i `isAvailable` peab olema `true`;
- koordinaadid ja pilt on selles töövoos valikulised.

Frontend'i valideerimine annab kasutajale kiire ja arusaadava tagasiside. Backend peab samu ärikriitilisi reegleid siiski iseseisvalt kontrollima. Frontend pole turvapiir: API-le võib päringuid saata ka ilma veebilehte kasutamata.

Backend võib tagastada näiteks:

- `403` — sama nimega asukoht on juba olemas;
- vea, kui viidatud `cityId` ei vasta olemasolevale linnale;
- `500` — ootamatu serveripoolne viga.

### Skeem

```text
Lisa-nupu vajutus
       │
       ▼
frontend kontrollib vormi
   ├─ vigane → näita konkreetset veateadet
   └─ sobib  → POST request
                    │
                    ▼
             backend kontrollib uuesti
                ├─ viga → error response
                └─ sobib → salvesta
```

## `AlertDanger` ja veateade kui olek — `2:14:07` {#alert-danger}

### Selgitus

Veateade salvestatakse `LocationView` data blokis muutujasse `errorMessage`. Kasutajaliidese komponent `AlertDanger` saab selle props'ina. Kui tekst on tühi, alert'i ei renderdata; kui tekstil on sisu, näidatakse punast Bootstrap teadet.

Sama muutuja täidab kaks rolli:

1. määrab, mida kasutajale näidata;
2. võimaldab otsustada, kas POST-päringut tohib saata.

### Koodinäide (`frontend/src/components/AlertDanger.vue`)

```vue
<script>
export default {
  name: 'AlertDanger',
  props: {
    errorMessage: String,
  },
}
</script>

<template>
  <div v-if="errorMessage !== ''" class="alert alert-danger" role="alert">
    {{ errorMessage }}
  </div>
</template>
```

Kasutamine vaates:

```vue
<AlertDanger :error-message="errorMessage" />
```

Koolon on vajalik, sest kaasa antakse muutuja väärtus, mitte tekst „errorMessage”.

## Esimene valideerimisreegel: linn peab olema valitud — `2:21:13` {#linna-valideerimine}

### Selgitus

Linnavaliku algväärtus on `cityId: 0`. Päris linnade ID-d algavad ühest, mistõttu null toimib sentinel value'na ehk erilise väärtusena, mis tähendab „valikut pole tehtud”.

Lisa-nupu vajutamisel kontrollib `addLocation()` mudelit. Kui `cityId` on null, antakse `errorMessage` muutujale konkreetne juhis.

### Koodinäide (`frontend/src/views/LocationView.vue`)

```js
addLocation() {
  this.resetErrorMessage()

  if (this.location.cityId === 0) {
    this.errorMessage = 'Vali linn'
  }
},
```

```vue
<button @click="addLocation" class="btn btn-success" type="submit">
  Lisa
</button>
```

### Päriselu analoogia

Null on siin nagu rippmenüü esimene rida „— vali linn —”. See ei ole päris valik, vaid kontrollitav märguanne, et kasutaja peab veel otsuse tegema.

## Veateate lähtestamine ja loetav abimeetod — `2:25:39` {#veateate-lahtestamine}

### Selgitus

Iga uus saatmiskatse peab algama puhtast veaseisust. Muidu jääks eelmise katse veateade nähtavaks ka pärast vea parandamist. Seetõttu seatakse `errorMessage` enne kontrolle tühjaks.

Üherealise omistuse võiks kirjutada otse `addLocation()` meetodisse, kuid nimeline `resetErrorMessage()` väljendab kavatsust selgemalt. Lugeja näeb kohe, miks tegevus toimub.

### Koodinäide

```js
addLocation() {
  this.resetErrorMessage()

  if (this.location.cityId === 0) {
    this.errorMessage = 'Vali linn'
  }
},

resetErrorMessage() {
  this.errorMessage = ''
},
```

Järgmised vormiväljad saab kontrollida `else if` harudega, kui soov on näidata korraga ainult esimest leitud viga:

```js
if (this.location.cityId === 0) {
  this.errorMessage = 'Vali linn'
} else if (this.location.locationName.trim() === '') {
  this.errorMessage = 'Sisesta asukoha nimi'
} else if (this.location.numberOfAtms < 1) {
  this.errorMessage = 'Automaatide arv peab olema vähemalt üks'
}
```

### Päriselu analoogia

Veateate lähtestamine on nagu tahvli puhtaks pühkimine enne uue ülesande kontrollimist. Vana märkus ei tohi mõjutada uut katset.
