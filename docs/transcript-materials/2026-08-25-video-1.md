## IntelliJ vs teised tooted (Ultimate litsents) — `0:07:36` {#intellij-ultimate}

### Selgitus

IntelliJ IDEA on JetBrainsi toode, mis on **algselt mõeldud Java ja Kotlini arenduseks**, kuid toetab tegelikult ka teisi keeli (nt Python). JetBrainsil on eraldi tooted erinevate keelte jaoks (nt WebStorm veebiarenduseks), aga koolituses kasutatakse **IntelliJ Ultimate** versiooni, mis toetab piisavalt hästi nii backend- kui frontend-arendust korraga.

**Ultimate** on tasuline versioon, mis lisab mugavusi nagu:
- Andmebaasi (database) tööriistad
- Serveri käivitamise hõlbustused
- Palju väiksemaid produktiivsust tõstvaid funktsioone

### Päriselu analoogia

Tasuta versioon on nagu põhitasemega auto — sõidab kohale, aga Ultimate on nagu lisavarustusega auto: mugavam, aga sõidad ikka sama teed.

## Git: haru kustutamine ja Local History turvavõrk — `0:15:06` {#haru-kustutamine}

### Selgitus

Kui haru on oma otstarbe täitnud (nt demo haru), saab selle kustutada. Oluline reegel: **ei saa kustutada haru, mille peal parasjagu asud** ("ei saa saagida oksa, mille peal istud") — enne kustutamist tuleb minna teisele harule (nt `master`).

Git eristab kahte tüüpi haru kustutamist:
- **Lokaalse haru kustutamine** — ei küsi kinnitust, sest see ei ole ohtlik (mõjutab ainult sinu arvutit)
- **Pilves oleva (remote) haru kustutamine** — küsib alati üle ("Kas sa tahad ka kustutada Track Branch?"), sest see on jagatud ressurss — kellegi kuu aega tehtud tööd ei tohi kogemata kaotada

**Local History** on IntelliJ sisseehitatud turvavõrk — isegi failide puhul, mida Git ei jälgi (versioneerib), salvestab IDE ise failide muutmisajaloo. Seda saab vaadata paremklõpsuga failil → **Local History → Show History**.

### Skeem

```
Git versioneerimine (commit'itud failid)
        |
        +-- turvaline ajalugu, jagatud teistega
        |
IntelliJ Local History (kõik failid, isegi jälgimata)
        |
        +-- viimane päästerõngas kogemata kustutamise vastu
```

### Päriselu analoogia

Git commit on nagu ametlik dokumendi versioon arhiivis — teistega jagatud ja usaldusväärne. Local History on nagu IDE enda "prügikast", mis hoiab alles ka mustandeid, mida keegi teine kunagi ei näinud.

## .gitignore: mida versioonihaldus ei jälgi — `0:36:05` {#gitignore}

### Selgitus

`.gitignore` fail määrab, milliseid faile/kaustu Git **ei versioneeri ega saada kunagi pilve**. See on tähtis, sest:

- Iga arendaja arvutis on isiklikud seadistused ja andmebaasi ühendused, mis ei ole projekti osa
- Automaatselt genereeritavad failid (nt kompileeritud kood, `node_modules` kaust) ei pea olema versioonihalduses — need luuakse serveri käivitamisel uuesti
- Projektis on tavaliselt mitu `.gitignore` faili (nt backend ja frontend kaustades eraldi), mis vastavad iga tehnoloogia enda vajadustele

Fail, mida Git ei jälgi, on IntelliJ's näidatud **punase värviga**; kui lisad selle `git add` käsuga jälgimisse, muutub see **roheliseks**.

### Koodinäide (kontseptuaalne)

```
# .gitignore näide
node_modules/       # taastatavad sõltuvused, ei ole vaja versioneerida
.idea/               # isiklikud IDE seadistused
target/              # kompileeritud Java kood
```

### Päriselu analoogia

`.gitignore` on nagu "mustandite kaust" laual, mida sa kunagi arhiivi (Git ajalukku) ei pane — see sisaldab asju, mis on sulle isiklikult vajalikud, aga ei kuulu ühisesse projekti.

## Markdown formaat ja Skill'i struktuur — `0:33:20` {#markdown}

### Selgitus

**Markdown (.md)** on kirjaviis, mis võimaldab tavalises tekstis struktuuri luua:
- `#`, `##`, `###` — suurused pealkirjad (suurim → väikseim)
- Koodiplokid (` ``` `) — koodinäidete eristamiseks tavatekstist

Markdown on populaarne, sest see on **lihtne tavatekst**, mida saab kirjutada ükskõik millises redaktoris, ning tehisintellekti tööriistad (nagu Claude Code) mõistavad selle struktuuri (pealkirjad, koodiplokid) väga hästi.

### Päriselu analoogia

Markdown on nagu käsikirjaline märkmik, kus alapealkirjad on alla joonitud ja tähtsad kohad on paksus kirjas — lihtne kirjutada, aga annab tekstile selge struktuuri.

## Java kompileerimine vs JavaScript interpreteerimine — `1:08:16` {#java-vs-js}

### Selgitus

See on tähtis kontseptuaalne erinevus kahe keele vahel:

**Java** on **kompileeritav keel**:
1. Arendaja kirjutab `.java` faili (inimloetav kood)
2. **Java kompilaator** teisendab selle **bytecode'iks** (`.class` fail) — see on juba masinlähedasem kood
3. **Java virtuaalmasin (JVM)** — eraldi versioon iga operatsioonisüsteemi jaoks (Windows, Linux, Mac) — käivitab selle bytecode'i, teisendades selle konkreetsele süsteemile sobivateks käskudeks

**JavaScript** on **interpreteeritav keel**:
- Koodi ei kompileerita ette ära — brauser **tõlgendab koodi "linnult"**, käivitamise hetkel

See erinevus seletab, miks **hot reload** töötab frontendis, aga mitte backendis (vt järgmine peatükk).

### Skeem

```
JAVA:
Lähtekood (.java) --kompilaator--> Bytecode (.class) --JVM--> Masinkäsud
   (Human Readable)                (platvormist sõltumatu)      (platvormispetsiifiline)

JAVASCRIPT:
Lähtekood (.js) --brauser tõlgendab käivitamise hetkel--> Käsud
   (ei kompileerita ette)
```

### Päriselu analoogia

Java kompileerimine on nagu raamatu tõlkimine mitmesse keelde ette ära, enne kui seda ükski lugeja loeb — tõlge tehakse üks kord, aga on alati valmis. JavaScript on nagu simultaantõlk, kes tõlgib kõnet reaalajas, samal ajal kui räägitakse — pole vaja ette valmistuda, aga peab iga kord tõlkima uuesti.

## Hot reload: miks frontend ei vaja serveri taaskäivitust — `1:05:24` {#hot-reload}

### Selgitus

**Hot reload** on frontendi arendustehnoloogia, mis lubab teha koodis muudatusi, **ilma serverit uuesti käivitamata** — muudatused on kohe nähtavad. See on võimalik just seetõttu, et JavaScript on interpreteeritav (vt eelmine peatükk) — brauser loeb koodi uuesti sisse ja tõlgendab seda kohe.

Backend'is (Java) sellist luksust pole: iga kord, kui koodi muudad, tuleb server uuesti käivitada, et Java kompilaator saaks uue bytecode'i genereerida.

### Päriselu analoogia

Hot reload on nagu digitaalne joonistustahvel, kus muudatus ilmub ekraanile kohe, samas kui backend'i muutmine on nagu maali õlivärviga — pead ootama, kuni eelmine kiht kuivab (kompileerub), enne kui saad uut kihti peale panna.

## HTML: head vs body sektsioon — `1:12:46` {#head-body}

### Selgitus

HTML dokument koosneb kahest peamisest osast:

- **`<head>`** — **suuresti nähtamatu** osa. Siia lähevad viited script'idele, stiilidele ja muu metaandmestik (nt `<title>`, mis on ainuke `head` sisu osa, mis reaalselt nähtav on — brauseri vahekaardil).
- **`<body>`** — **nähtav** osa, mis kuvatakse veebilehel

### Skeem

```html
<html>
  <head>            <!-- nähtamatu: title, linkid stiilidele/scriptidele -->
    <title>Minu leht</title>
  </head>
  <body>            <!-- nähtav sisu -->
    <p>Tere, maailm!</p>
  </body>
</html>
```

### Päriselu analoogia

`<head>` on nagu raamatu tiitellehe taga olev tehniline info (ISBN, kirjastus) — vajalik, aga tavaline lugeja seda "kaante vahel lugedes" ei näe. `<body>` on nagu raamatu sisu ise — see, mida lugeja tegelikult loeb.

## Klaviatuuri trikid IntelliJ's — `0:13:49` {#klaviatuuri-trikid}

### Selgitus

Õpetaja rõhutab, et efektiivne arendaja väldib võimalikult palju hiire kasutamist ja kasutab klaviatuuri otseteid. Mainitud olulisemad trikid:

| Otsetee | Tegevus |
|---|---|
| `Ctrl + W` (macOS: sarnane) | Selekteerib sõna kursori kohalt, korduval vajutusel laiendab selektsiooni sõnahaaval väljapoole |
| `Ctrl + Shift + W` | Selektsiooni ahendamine (vastupidine) |
| `Ctrl + D` | Dubleerib rea |
| `Ctrl + /` (või `Ctrl+Shift+7`) | Kommenteerib rea (ees / väljas) |
| `Alt + Tab` (hoides Alt all) | Navigeerimine avatud akende vahel |
| `Windows` + nool | Akna paigutamine poolele ekraanile |

Õpetaja soovitab investeerida aega otseteede õppimisse — esialgu on see aeglasem (peab otsima, kuidas midagi teha), aga distsiplineeritud harjutamine tasub end kiirelt ära, sest liigutus jääb "käte mällu".

### Päriselu analoogia

Klaviatuuri otseteede õppimine on nagu autojuhtimise õppimine käigukastiga — alguses tundub tülikas mõelda igale liigutusele, aga peagi muutub see automaatseks refleksiks, mis säästab palju aega.

## HTML elemendid: heading, paragraph, span, list — `1:35:48` {#html-elemendid}

### Selgitus

Ülevaade põhilistest HTML elementidest (samad, mis videos 2, aga siin eraldi selgitatud):

- **`<h1>`–`<h6>`** — pealkirjad, kus number näitab tähtsuse taset (h1 kõige suurem/tähtsam)
- **`<p>`** — tekstilõik (paragraaf), tekitab automaatselt reavahetuse enne ja pärast
- **`<span>`** — tekstisisene "ulatus" (scope), mis **ei tekita mingit visuaalset muutust ise**, aga võimaldab osale tekstile eraldi stiili anda
- **`<br>`** — reavahetus (ühe tagiga element, ei vaja lõputähist)
- **`<ul>`** (unordered list) — punktloetelu (bullet points)
- **`<ol>`** (ordered list) — nummerdatud loetelu
- **`<li>`** (list item) — iga loetelu üksus

### Koodinäide

```html
<p>Siin on meie <span style="color: red">90'ndate stiilis</span> pank.</p>

<ol>
    <li>Tallinn</li>
    <li>Tartu</li>
    <li>Viljandi</li>
</ol>
```

### Ühe- vs kahe-tagiga elemendid

- **Ühe tagiga elemendid** (nt `<br>`, `<img>`) — ei sisalda midagi enda vahel, ei vaja lõputähist
- **Kahe tagiga elemendid** (nt `<p>...</p>`, `<span>...</span>`) — vajavad algus- ja lõputähist, sest nende "mõju" peab olema selgelt piiritletud

### Päriselu analoogia

`<span>` on nagu läbipaistev pliiatsipulk paberil — see joonib alla ainult ühe konkreetse sõna, ilma et muudaks ülejäänud lehe välimust.

## Pildi (img) element ja ligipääsetavus — `2:04:08` {#img-element}

### Selgitus

`<img>` on **ühe tagiga element** (nagu `<br>`), millel on tähtsad atribuudid:

- **`src`** (source) — pildi allikas: kas väline URL, kohalik fail projektis, või hiljem andmebaasist tulev pilt
- **`alt`** (alternative text) — asendustekst, mis kuvatakse, kui pilti ei suudeta renderdada, ning mida **ekraanilugejad (screen reader)** loevad ette vaegnägijatele
- **`width`** / `height` — pildi suurus (soovitatakse pigem lahendada CSS-iga, mitte otse HTML atribuutidena)

### Koodinäide (kontseptuaalne)

```html
<img src="kaart.jpg" alt="Eestimaa kaart LHV pangakontoritega" width="200">
```

### Kolm võimalust, kust pilt tuleb

1. **Kohalik fail** — pilt on projekti enda serveris/kaustas olemas
2. **Väline link** — pilt asub kuskil teisel serveril (nt CDN)
3. **Andmebaasist** — pildi andmed tulevad andmebaasist (käsitletakse hiljem)

### Päriselu analoogia

`alt` tekst on nagu subtiitrid filmis — enamik inimesi ei vaja neid, aga need on hädavajalikud neile, kes ei saa pilti/heli tavapärasel viisil tarbida (siin: vaegnägijad, kes kasutavad ekraanilugejat).

## Tabel: table, tr, td struktuur — `2:13:53` {#tabel}

### Selgitus

HTML tabel koosneb kolmest tasemest:

- **`<table>`** — kogu tabel
- **`<tr>`** (table row) — üks rida
- **`<td>`** (table data) — üks lahter (veerg) rea sees

### Skeem

```
<table>                    <- kogu tabel
  <tr>                      <- rida 1
    <td>Eesnimi</td>        <- veerg 1
    <td>Perekonnanimi</td>  <- veerg 2
  </tr>
  <tr>                      <- rida 2
    <td>Rain</td>
    <td>Tüür</td>
  </tr>
</table>
```

### Koodinäide (projektist, `frontend/index.html:35-64`)

```html
<table class="table table-dark table-hover">
    <thead>
    <tr>
        <th scope="col">#</th>
        <th scope="col">First</th>
        <th scope="col">Last</th>
        <th scope="col">Handle</th>
    </tr>
    </thead>
    <tbody>
    <tr>
        <th scope="row">1</th>
        <td>Mark</td>
        <td>Otto</td>
        <td>@mdo</td>
    </tr>
    </tbody>
</table>
```

### Päriselu analoogia

Tabel on nagu Exceli tabel: `<table>` on terve leht, `<tr>` on iga rida, `<td>` on iga üksik lahter reas.

## Input element ja label/id seos — `2:19:11` {#input-label}

### Selgitus

`<input>` element on **ühe tagiga**, kus vaikimisi `type` on `text`. Sellel on tähtis atribuut **`id`**, mis peab olema **unikaalne kogu HTML dokumendis** — see toimib "sildina" (nagu muutuja nimi), mille abil saab programmiliselt hiljem konkreetsele kastile viidata.

`<label>` element seotakse `input`-iga `for` atribuudi kaudu, mis peab kattuma `input`-i `id`-ga.

### Koodinäide (projektist, `frontend/index.html:68-77`)

```html
<label for="firstName">Eesnimi</label>
<input type="text" id="firstName" placeholder="Eesnimi">
<br>

<label for="lastName">Perekonnanimi</label>
<input type="text" id="lastName" placeholder="Tamm">
```

### Päriselu analoogia

`id` on nagu isikukood konkreetsele elemendile — kui hiljem tahad programmis öelda "võta selle konkreetse kasti sisu", vajad täpselt seda unikaalset viidet, muidu ei tea programm, millisest kastist täpselt juttu on.

## Muutujate nimetamise tavad: camelCase, PascalCase, snake_case, kebab-case — `2:24:28` {#nimetamise-tavad}

### Selgitus

Kuna koodis ei saa muutujate nimedes kasutada tühikuid, on välja kujunenud erinevad **nimetamiskonventsioonid**, kuidas mitmesõnalisi nimesid eristada:

| Stiil | Näide | Reegel |
|---|---|---|
| **camelCase** | `firstName` | Esimene sõna väiketähega, iga järgnev sõna algab suure tähega |
| **PascalCase** | `FirstName` | Iga sõna (sh esimene) algab suure tähega |
| **snake_case** | `first_name` | Sõnad eraldatakse alakriipsuga, kõik väiketähed |
| **kebab-case** | `first-name` | Sõnad eraldatakse sidekriipsuga |

Koodis kirjutatakse muutujate nimed alati **inglise keeles**, isegi kui sisu (nt kasutajaliidese tekstid) on eesti keeles.

Selles projektis kasutatakse `input` elementide `id` väärtuste jaoks **camelCase**-i (nt `firstName`, `lastName`).

### Päriselu analoogia

Nimetamiskonventsioonid on nagu erinevad viisid kirjutada liitsõnu — "grillvarras" vs "grill-varras" vs "Grill Varras" tähendavad sama asja, aga kokkulepitud stiil aitab kõigil kiiremini lugeda ja mõista, kus üks sõna lõppeb ja teine algab.
