## Props: andmete ühesuunaline voog vanemalt lapsele — `0:00:47` {#props}

### Selgitus

**Props** (lühend sõnast *properties*, e. omadused) on Vue komponendi mehhanism, mis lubab **vanemkomponendil** (parent) anda andmeid **lapskomponendile** (child). See on täpselt samasugune "sildikeste loomise koht" nagu `data` blokk — ainult et kui `data` blokis saab muutuja väärtust ise (skripti seest) muuta, siis **props ei tohi kunagi lapskomponendi enda failis muutuda**.

Props defineeritakse `export default` sektsiooni sees, `props` võtme all, kus iga silt saab endale tüübi:

```js
export default {
  name: 'AlertDanger',
  props: {
    errorMessage: String,
  },
}
```

Silt (nt `errorMessage`) kirjeldab, **mis info seal sees on** (mitte tüüpi ennast) — tüüp (`String`, `Number`, `Object` jne) määrab, mis kuju see info võib võtta.

### Skeem

```
┌─────────────────────┐
│  LoginView.vue       │  ← parent (isik, kes annab andmeid)
│  data: errorMessage   │
│                       │
│  <AlertDanger         │
│    :error-message=    │  ← koolon = "ära anna teksti, anna muutuja väärtus"
│      "errorMessage" /> │
└──────────┬────────────┘
           │  vool ainult ülevalt alla
           ▼
┌─────────────────────┐
│ AlertDanger.vue       │  ← child (saab props'i, ei muuda seda)
│  props: errorMessage  │
└─────────────────────┘
```

### Koodinäide

Repos on see täpselt niimoodi realiseeritud (`frontend/src/components/AlertDanger.vue`):

```vue
<script>
export default {
  name: 'AlertDanger',
  props: {
    errorMessage: String,
  },
}
</script>

<template>
  <div>
    <div v-if="errorMessage !== ''" class="alert alert-danger" role="alert">{{ errorMessage }}</div>
  </div>
</template>
```

### Päriselu analoogia

Props on nagu kiri, mis saabub postkasti (child) — kirja saaja ei tohi kirja sisu ise ümber kirjutada ja saata originaali tagasi saatjale muudetuna. Kui vastust on vaja, tuleb kirjutada **uus** kiri (uus sõnum/event), mitte võltsida vana.

## Props ei tohi muutuda (mutation) — `0:05:52` {#props-ei-tohi-muutuda}

### Selgitus

Kui lapskomponendis üritada propsi väärtust otse muuta (nt `this.message = "uus väärtus"`), annab Vue veateate: **"Unexpected mutation of prop"**. Programmeerimises kutsutakse sellist objekti, mille sisu ei tohi muutuda, **immutable'iks**.

Miks see keeld on olemas? Kuna props "voolab ülevalt alla" (parentilt childile), tekiks vastupidise muutmise korral **ringsõltuvus** — programm ei teaks, kas väärtus tuli ülevalt või muudeti kohapeal, ja see võib tekitada lõputu renderdustsükli (component üritab end iga kord uuesti joonistada).

Propsi väärtust *saab* küll kasutada — kuvamiseks, tingimuste kontrollimiseks, arvutusteks — aga mitte kunagi ümber kirjutada.

### Päriselu analoogia

Vool jõel läheb alati ühte suunda — allavoolu. Kui lapskomponent üritaks propsi muuta, oleks see nagu üritada jõevett tagasi mäkke suunata: tehnoloogia pole selleks disainitud ja tekitab kaose.

## Kuidas Propsile viidata: `{{ }}` ja `:koolon` — `0:14:04` {#props-vitamine}

### Selgitus

Vue'l on kaks konteksti, kus tuleb Propsile või andmemuutujale **viidata**, mitte lihtsalt teksti kirjutada:

1. **Tag'ide (siltide) vahel** template'is: kasutatakse **topelt loogilisi sulge** `{{ }}`.
2. **Tag'i sees** (atribuudina): kasutatakse **kooloni** `:` atribuudi nime ees.

Kui unustad viitamismärgi ära panna, käitub Vue nii, nagu tahaksid sinna panna **staatilise teksti** (string), mitte muutuja väärtust. Visuaalne vihje: kui kirjutatud tekst on **roheline**, on see lihtsalt string — see on märk, et unustasid `:` või `{{ }}` ette panna.

### Koodinäide

```html
<!-- tag'ide vahel: topelt loogilised sulud -->
<div>{{ errorMessage }}</div>

<!-- tag'i sees: koolon enne atribuudi nime -->
<AlertDanger :error-message="errorMessage" />

<!-- ilma kooloniga oleks see lihtsalt string "errorMessage", mitte viide muutujale! -->
<AlertDanger error-message="errorMessage" />  <!-- VALE -->
```

### Päriselu analoogia

Koolon (`:`) on nagu käsi, mis osutab kellelegi ja ütleb "see, mitte tema nimi paberil" — ilma selleta loeb Vue sinu kirjutatud sõna lihtsalt tähtede jadana, mitte viitena.

## `Extract New Component` refaktor ja alamkomponendi loomine — `0:32:57` {#extract-component}

### Selgitus

Kui üks visuaalne osa (nt `<div>` alert-teatega) hakkab kordama end mitmes kohas rakenduses, tasub see teha **eraldi taaskasutatavaks komponendiks**. IDE (IntelliJ) tööriist `Extract New Component` teeb suurema osa tööst automaatselt:

1. Selekteeri sobiv HTML plokk (peab olema **üks juurelement**, mitte mitu erinevat `<div>`).
2. Parem klõps → **Refactor → Extract New Component**.
3. IDE loob uue `.vue` faili, tõstab sinna HTML `<template>` sisse, tekitab `props` automaatselt (kui vana koodis kasutati mõnda muutujat, pakub see sama nime propsina).
4. IDE lisab automaatselt vajaliku `import` ja registreerib komponendi `components` blokki.

**Oluline reegel:** `<template>` tagi sees tohib olla **ainult üks laps (child)** — ei saa lihtsalt suvalisi ridu selekteerida, peab olema terviklik `<div>`.

### Päriselu analoogia

See on nagu Wordi dokumendist ühe lõigu välja lõikamine ja uude faili panemine — kui lõik on terviklik (algab ja lõpeb korrektselt), töötab lõikamine sujuvalt; kui üritad võtta poole lause keskelt, jääb midagi katki.

## Kumb on parent, kumb child — nimede refaktoreerimine (Shift+F6) — `0:35:26` {#parent-child}

### Selgitus

**Parent** (vanem) on fail, mis kutsub teist komponenti välja. **Child** (laps) on komponent, mida välja kutsutakse. Kui `LoginView.vue` kutsub välja `<AlertDanger />`, siis `LoginView` on parent ja `AlertDanger` on child.

Sama muutuja nimi võib mõlemas failis eksisteerida, aga **eri kontekstis**:
- Parendis (`LoginView.vue`, `data` blokis): `errorMessage`
- Childis (`AlertDanger.vue`, `props` blokis): `errorMessage`

Kuna need on **kaks erinevat silti**, mis lihtsalt kannavad sama nime, soovitab IDE erinevaid kirjaviise, et neid visuaalselt eristada — nt `error-message` (kebab-case, kasutatakse tag'i atribuudina väljakutsumisel) vs `errorMessage` (camelCase, kasutatakse `props` definitsioonis).

**IDE tööriist `Shift+F6`** (Rename) muudab muutuja nime üle terve projekti korraga — soovitatakse alati kasutada seda tööriista, mitte käsitsi otsi-asenda, sest käsitsi on ohtlik teha viga (nt asendada vale kohta).

### Koodinäide

```vue
<!-- LoginView.vue (PARENT) -->
<AlertDanger :error-message="errorMessage" />
<!--          ^kebab-case      ^camelCase muutuja parendi data blokis -->

<!-- AlertDanger.vue (CHILD) -->
<script>
export default {
  props: {
    errorMessage: String,  // ^camelCase, sest see on JS objekti võti
  },
}
</script>
```

### Päriselu analoogia

Kaks inimest võivad kanda sama nime (nt "Mari"), aga on ikkagi kaks erinevat inimest. Kirjaviisi erinevus (`error-message` vs `errorMessage`) on nagu erinev hüüdnimi samale inimesele eri kontekstides — aitab kiirelt aru saada, kummast "Marist" jutt käib.

## HTTP sõnumid ja staatuskoodid — `0:44:07` {#http-sonumid}

### Selgitus

**HTTP** on protokoll — kokkulepitud "keel", kuidas kaks süsteemi (nt brauser ja server) omavahel suhtlevad. Iga HTTP sõnum koosneb kolmest osast:

1. **Algusrida** — mida tahetakse (meetod + tee, nt `GET /api/login`)
2. **Päised (headers)** — lisainfo sõnumi kohta
3. **Valikuline keha (body)** — sõnumi tegelik sisu, tihti JSON formaadis

**Peamised HTTP meetodid:**
- `GET` — näita mulle andmeid
- `POST` — lisa uus andmekirje
- `PUT` — asenda täielikult
- `DELETE` — kustuta

**Staatuskoodid** (server vastab alati koodiga):

| Vahemik | Tähendus |
|---|---|
| 1xx | Informatiivsed |
| 2xx | Õnnestus (nt 200 OK, 201 Created) |
| 3xx | Ümbersuunamine |
| 4xx | Kliendi viga (nt 400 Bad Request, 403 Forbidden, 404 Not Found) |
| 5xx | Serveri viga (server ise läks katki) |

Vahe 4xx ja 5xx vahel: 4xx tähendab, et **klient küsis valesti** (server on elus ja kuulab, aga päring ei vastanud nõuetele), 5xx tähendab, et **serveris endas läks midagi katki** — see pole kliendi süü.

### Päriselu analoogia

HTTP sõnum on nagu kiri: algusrida on ümbrik ("kellele, mis eesmärgil"), päised on lisainfo väljaspool ümbrikku (nt "kiireloomuline"), keha on kirja sisu. Staatuskood on vastuskiri, mis alati algab lühikese sõnaga "kõik hästi" (2xx) või "midagi valesti — sina eksisid" (4xx) või "midagi valesti — mina eksisin" (5xx).

## Axios: mis see on ja miks seda kasutame — `0:50:28` {#axios}

### Selgitus

Brauseris on sisse ehitatud tehnoloogia HTTP päringute tegemiseks (`fetch`), aga see on suhteliselt madala taseme tööriist. **Axios** on selle peale ehitatud teek (library), mis lisab mugavusi:

- Teeb automaatselt JSON → JavaScript objekt teisenduse ja vastupidi
- Struktureerib vastuse käsitlemise selgelt `.then()` (õnnestus) ja `.catch()` (viga) plokkideks
- Võimaldab lisada globaalseid "kuulajaid" (interceptors), nt autentimistõendi (token) automaatseks uuendamiseks

Projektis on axios registreeritud globaalse omadusena — kasutatakse otse importides:

```js
import axios from 'axios'
```

### Koodinäide (`frontend/src/views/LoginView.vue`)

```js
axios
  .post('/api/login', this.loginRequest)
  .then((response) => this.handleLoginResponse(response))
  .catch()
  .finally(() => this.stopSpinner())
```

### Päriselu analoogia

Kui `fetch` on nagu käsitsi kirjutatud telefonikõne skript (pead ise kõik sõnad ette valmistama), siis axios on nagu sekretär, kes juba teab kokkuleppelist vormi ja tõlgib sinu eest automaatselt.

## Meetodi väljakutse ja parameetrite tüübid (url, data, config) — `0:56:31` {#meetodi-parameetrid}

### Selgitus

Kui kutsud välja mõne meetodi (nt `axios.post(...)`), on kasulik enne kirjutamist vaadata, **mitu parameetrit see ootab ja mis tüüpi**. IDE-s saab seda vaadata `Ctrl+B` (või hiirega peale liikudes) — IDE näitab helehallis tekstis vihjeid.

Komadega loendamine aitab kiirelt aru saada, mitu parameetrit meetod ootab: `axios.post(url, data, config)` — kolm parameetrit, eraldatud komadega.

- **`url`** (`String`) — kuhu sõnum saadetakse, nt `'/api/login'`
- **`data`** (`any`) — mis andmed kaasa lähevad (JSON kehas)
- **`config`** (valikuline, objekt) — lisaseadistused (nt päised)

**Küsimärk** parameetri tüübi järel (nt `config?`) tähendab, et parameeter on **valikuline** — kui seda pole vaja, ei pea seda üldse kirjutama (ei saa aga lihtsalt komaga vahele jätta, kui hiljem veel parameetreid tuleb).

### Koodinäide

```js
axios.post('/api/login', this.loginRequest)
//          ^url          ^data (objekt, mis läheb JSON kehana kaasa)
```

### Päriselu analoogia

Meetodi parameetrite vaatamine enne väljakutsumist on nagu retsepti lugemine enne küpsetamise alustamist — pead teadma, mitu koostisosa (parameetrit) on vaja ja mis järjekorras.

## FEB-7: login() meetodi ehitamine — `0:55:26` {#feb-7}

### Selgitus

Selle taski (FEB-7) eesmärk oli ehitada `LoginView.vue` `login()` meetod, mis:

1. Kontrollib, et kõik väljad on täidetud
2. Saadab POST sõnumi `/api/login` koos `username` ja `password` andmetega
3. Kui vastus on edukas (2xx), salvestab tulemuse
4. Suunab kasutaja pangaautomaatide (ATM) vaatele

### Koodinäide — praegune lõplik lahendus (`frontend/src/views/LoginView.vue`)

```js
export default {
  name: 'LoginView',
  components: { AlertDanger },
  methods: {
    login() {
      this.resetMessage()
      if (this.allFieldsHaveInput()) {
        this.startSpinner()

        axios
          .post('/api/login', this.loginRequest)
          .then((response) => this.handleLoginResponse(response))
          .catch()
          .finally(() => this.stopSpinner())
      } else {
        this.errorMessage = 'Täida kõik väljad'
      }
    },

    allFieldsHaveInput() {
      return this.loginRequest.username.length > 0 && this.loginRequest.password.length > 0
    },

    handleLoginResponse(response) {
      this.loginResponse = response.data
      sessionStorage.setItem('userId', this.loginResponse.userId)
      sessionStorage.setItem('roleName', this.loginResponse.roleName)

      router.push({
        name: 'atmsRoute'
      })
    },

    startSpinner() {
      this.showSpinner = true
    },

    stopSpinner() {
      this.showSpinner = false
    },

    resetMessage() {
      this.errorMessage = ''
    },
  },
  data() {
    return {
      errorMessage: '',
      showSpinner: false,
      loginRequest: {
        username: '',
        password: '',
      },
      loginResponse: {
        userId: 0,
        roleName: '',
      },
    }
  },
}
```

Meetodite järjekord failis pole juhuslik — õpetaja rõhutas, et neid tasub paigutada **loogilises lugemisjärjekorras** (peamine meetod kõige eespool, abimeetodid allpool), et faili lugeja saaks jälgida "lugu" ülevalt alla, nagu raamatut.

## Promise, `.then()` / `.catch()` / `.finally()` ja asünkroonsus — `1:09:55` {#promise}

### Selgitus

Kui sõnum saadetakse serverisse, ei jää programm **ootama**, kuni vastus tuleb — see on **asünkroonne** (asynchronous) käitumine. Selle asemel saab kõne tegija kohe tagasi **promise'i** (lubaduse): "ma annan sulle teada, kui vastus tuleb".

Kolm plokki, mida saab `.then()` järel ketistada:

- **`.then(response => ...)`** — käivitub, kui vastus tuleb edukalt (2xx staatus)
- **`.catch(error => ...)`** — käivitub, kui tuleb viga (4xx või 5xx staatus)
- **`.finally(() => ...)`** — käivitub **alati**, sõltumata tulemusest (kasulik nt spinner-i peitmiseks)

Ainult üks `.then()` või `.catch()` saab käivituda — need on teineteist välistavad, nagu `if`/`else`.

### Skeem

```
axios.post(url, data)
        │
        ▼
   [promise antakse kohe tagasi, kood jätkub edasi]
        │
        │   ... aeg möödub ...
        │
        ▼
   vastus saabub
        │
   ┌────┴────┐
   ▼         ▼
 2xx       4xx/5xx
 .then()   .catch()
   │         │
   └────┬────┘
        ▼
   .finally()  ← käivitub alati
```

### Päriselu analoogia

Kõne tegemine telefonis on nagu promise: helistad kellelegi (saadad sõnumi), aga ei jää toru juurde kõrva külge seisma — jätkad muude asjadega ja kui teine pool vastab (`.then()`) või kõne ei õnnestu (`.catch()`), reageerid sellele hetkel, kui see juhtub.

## Spinner: laadimise indikaator nupul — `1:15:47` {#spinner}

### Selgitus

Kuna sõnumi vastus võib võtta aega (eriti kui server on kaugel — nt kasutaja Austraalias), on hea tava näidata **visuaalset tagasisidet**, et midagi toimub. Levinud lahendus: peita nupp ja näidata selle asemel **spinnerit** (pöörlevat animatsiooni), et kasutaja ei saaks nuppu mitu korda klõpsida.

See nõuab uut `data` muutujat (`showSpinner`), mida muudetakse enne sõnumi saatmist (`true`) ja pärast vastuse saamist (`false`, `.finally()` plokis).

### Koodinäide (`frontend/src/views/LoginView.vue`)

```html
<button v-if="showSpinner" class="btn btn-primary" type="button" disabled>
  <span class="spinner-border spinner-border-sm" aria-hidden="true"></span>
  <span role="status">Login sisse...</span>
</button>
<button v-else @click="login" type="submit" class="btn btn-primary">Logi sisse</button>
```

```js
startSpinner() {
  this.showSpinner = true
},
stopSpinner() {
  this.showSpinner = false
},
```

`v-if` / `v-else` peavad olema **kohe kõrvuti** template'is, muidu Vue ei saa aru, et need kuuluvad kokku.

### Päriselu analoogia

Spinner on nagu liftinupu tagasiside — kui vajutad nuppu ja tuli süttib, tead, et lift on teel, ega vajuta nuppu 10 korda uuesti. Ilma selleta tunneksid, et midagi ei toimu, ja klõpsiksid närviliselt uuesti.

## Ternaarne loogika ja "kui tuleb roheline tekst, on midagi valesti" — `1:28:47` {#ternaarne-loogika}

### Selgitus

Õpetaja demonstreeris (meelega vale näitena!) tarbetut koodi kirjutamist:

```js
// LIIGSELT KEERULINE — ÄRA TEE NII
if (showSpinner === true) {
  return true
} else {
  return false
}
```

See on üleliigne, sest `showSpinner === true` juba **iseenesest** rehkendub kas `true` või `false` väärtuseks — pole vaja seda `if`-iga uuesti kontrollida ja tagastada sama väärtus. Kui muutuja väärtus juba **ongi** boolean (tõeväärtus), saab seda otse kasutada:

```js
// LIHTNE JA ÕIGE
return showSpinner === true  // või lihtsalt: return showSpinner
```

Üldine reegel: kui meetod midagi **tagastab** (`return`) ja tahad seda edasi kasutada, pane see muutujasse — see on hea algne samm, isegi kui hiljem lühendad koodi.

### Päriselu analoogia

Küsida "kas see on tõsi, et see on tõsi?" on sama, mis küsida lihtsalt "kas see on tõsi?" — teine küsimine ei lisa infot, ainult keerukust.

## Lambda (nooleavaldis) `.then()` sees — `1:51:25` {#lambda}

### Selgitav

**Lambda funktsioon** (ka nooleavaldis, arrow function) on anonüümne (nimetu) funktsioon, mida kasutatakse kohapeal, ilma eraldi nime andmata. Süntaks: `(parameeter) => { kood }`.

Kui kood mahub **ühele reale**, ei ole tarvis loogilisi sulge (`{}`) ega `return`-sõna — tulemus tagastub automaatselt:

```js
.then((response) => this.handleLoginResponse(response))
```

Kui kood läheks **mitmele reale**, on vaja loogilisi sulge, ja soovitatavalt tuleks siis luua **eraldi meetod** — üherealine `.then()` väljakutse on loetavam kui pikk mitmerealine plokk otse `.then()` sees.

### Koodinäide: tühjade sulgudega lambda

Kui parameetrit pole (nt `.catch()` ilma error-käsitluseta), näitab see, et parameetrit ei kasutata:

```js
.catch()   // tühjad sulud — pole veel viga käsitletud (see on teadlikult lihtsustatud demo variant)
.finally(() => this.stopSpinner())  // tühjad sulud enne noolt = "pole vaja andmeid, lihtsalt käivita"
```

### Päriselu analoogia

Lambda on nagu kiire post-it märkus ukse peal ("kohe tagasi") — ei vaja pikka ametlikku kirja (eraldi nimega meetodit), kui sõnum on lühike ja kohapealne.

## Debugger ja breakpointid — `2:11:32` {#debugger}

### Selgitus

**Breakpoint** (peatuspunkt) on IDE tööriist, mis peatab koodi täitmise täpselt sellel real, et saaks reaalajas vaadata muutujate väärtusi. See on eriti kasulik asünkroonse koodi (Promise) sisu uurimiseks, kus muidu on raske "näha", mis serverist tagasi tuli.

Sammud IDE-s:
1. Klõpsa reanumbri kõrvale, et lisada punane ring (breakpoint)
2. Käivita rakendus **debug-režiimis**
3. Kui kood jõuab breakpointini, peatub täitmine, ja saab muutujaid uurida (nt vaadata `response` objekti sisu)
4. `Next` (samm edasi) liigutab täitmist rida-realt edasi

### Päriselu analoogia

Breakpoint on nagu pausinupp filmi vaatamisel täpselt olulisel hetkel — selle asemel, et kogu filmi kiirelt läbi vaadata ja loota, et märkad detaili, peatad täpselt õigel kaadril ja uurid seda rahulikult.

## Andmemudeli defineerimine (`loginResponse`) — `2:18:38` {#andmemudel}

### Selgitus

Kui serverist tulnud vastuse (`response.data`) struktuur pole koodifailist otse loetav (nt kui kasutad seda ainult muutujana `response`), on kasulik luua **andmemudel** — `data` bloki muutuja, mis **dokumenteerib**, mis väljad sealt vastusest oodatakse:

```js
data() {
  return {
    loginResponse: {
      userId: 0,        // number — vaikeväärtus 0, näitab tüüpi
      roleName: '',      // string — vaikeväärtus tühi string
    },
  }
}
```

Vaikeväärtused (`0`, `''`) ei ole lõplikud väärtused — need on **tüübiindikaatorid**, mis annavad koodi lugejale (ja iseendale tulevikus) kohe aimu, mis tüüpi andmed sinna lähevad. Reaalne sisu tuleb alati **väljastpoolt** (serveri vastusest), mitte programmi enda seest.

### Oht: nimede lahknevus (mismatch)

Kui backend saadab välja `UserId` (suure algustähega), aga frontendi mudel ootab `userId` (väikse algustähega), lähevad need kaks omavahel lahku ja kood ei tööta, isegi kui kood ise on "õige". Kui teed backendis muudatuse, tuleb alati **otsida üle terve frontend**, kas seda teenust kuskil juba kasutatakse (nt `Ctrl+F` failinimede sees).

### Koodinäide

```js
handleLoginResponse(response) {
  this.loginResponse = response.data
  // response.data === { userId: 1, roleName: "admin" }
}
```

## sessionStorage: andmete salvestamine brauseris — `2:29:37` {#sessionstorage}

### Selgitus

**`sessionStorage`** on brauseri sisse ehitatud "koht", kus saab andmeid salvestada **key-value** (võti-väärtus) paaridena. Andmed säilivad seni, kuni brauseri vahekaart (tab) on avatud — see kaob kaardi sulgemisel (erinevalt `localStorage`-st, mis säilib alati).

Peamised meetodid:

| Meetod | Mida teeb | Sisendparameetrid |
|---|---|---|
| `setItem(key, value)` | salvestab väärtuse võtme alla | võti (String), väärtus (String) |
| `getItem(key)` | võtab väärtuse võtme järgi kätte | võti (String) |
| `removeItem(key)` | kustutab ühe konkreetse võtme | võti (String) |
| `clear()` | kustutab kõik | — |

**Oluline:** kõik, mis `sessionStorage`-sse salvestatakse, muutub **stringiks**, isegi kui andsid kaasa numbri või boolean'i. Tagasi lugedes tuleb see vastavalt tüübile teisendada, kui vaja on temaga arvutusi teha.

### Koodinäide (`frontend/src/views/LoginView.vue` ja `AtmsView.vue`)

```js
// LoginView.vue — salvestamine pärast õnnestunud sisselogimist
handleLoginResponse(response) {
  this.loginResponse = response.data
  sessionStorage.setItem('userId', this.loginResponse.userId)
  sessionStorage.setItem('roleName', this.loginResponse.roleName)
  router.push({ name: 'atmsRoute' })
}
```

```js
// AtmsView.vue — kättesaamine uuel lehel
data() {
  return {
    userId: sessionStorage.getItem('userId'),
    roleName: sessionStorage.getItem('roleName'),
  }
}
```

### Päriselu analoogia

`sessionStorage` on nagu hotellitoa seif — paned sinna võtmega asju sisse, saad neid välja võtta terve viibimise (session) jooksul, aga väljaregistreerimisel (kaardi sulgemisel) seif tühjeneb.

## Vue Router: `router.push()` uuele lehele suunamiseks — `2:41:01` {#router-push}

### Selgitus

Pärast edukat sisselogimist tuleb kasutaja **programmiliselt suunata** uuele lehele (route'ile) — selle jaoks kasutatakse `router.push()` meetodit. Meetod ootab objekti, kus **`name`** väli viitab route'i nimele (mitte otse URL-teele!) — see on defineeritud `router/index.js` failis.

**Miks nime, mitte otse rada (path) kasutada?** Kui rada muutub tulevikus (nt konventsiooni ühtlustamise tõttu), piisab muudatuse tegemisest **ühes kohas** (`router/index.js`), selle asemel et otsida üles kõik kohad, kus vana rada oli otse kirjas.

### Skeem

```
router/index.js:
  { path: '/atms', name: 'atmsRoute', component: AtmsView }
                          ▲
                          │  viidatakse NIME järgi, mitte tee järgi
                          │
LoginView.vue:
  router.push({ name: 'atmsRoute' })
```

### Koodinäide (`frontend/src/router/index.js`)

```js
const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    { path: '/', name: 'homeRoute', component: HomeView },
    { path: '/error', name: 'errorRoute', component: ErrorView },
    { path: '/atms', name: 'atmsRoute', component: AtmsView },
    { path: '/login', name: 'loginRoute', component: LoginView },
  ],
})
```

```js
// LoginView.vue
router.push({
  name: 'atmsRoute'
})
```

### Päriselu analoogia

Route'i nime kasutamine on nagu inimese nime kasutamine helistades, mitte tema hetkelist telefoninumbrit — kui number vahetub (rada muutub), jääb nimi samaks ja kõik, kes selle nime teavad, jõuavad ikka õige inimeseni.

## Lifecycle hookid: `mounted` vs `beforeMount` — `3:02:56` {#lifecycle-hookid}

### Selgitus

Vue komponendil on erinevad **elutsükli hetked** (lifecycle hooks), kuhu saab koodi panna, mis käivitub automaatselt teatud hetkel:

- **`mounted()`** — käivitub **pärast** seda, kui `template` on juba mällu renderdatud. Turvaline koht, kust saab viidata HTML elementidele (nt `$refs` kaudu).
- **`beforeMount()`** — käivitub **enne** template'i renderdamist. Kiirem, aga **ei tohi viidata HTML elementidele**, sest neid pole veel olemas — see põhjustaks vea.

### Koodinäide (`frontend/src/views/AtmsView.vue`)

```js
export default {
  name: 'AtmsView',
  methods: {
    showAlert() {
      alert('userId: ' + this.userId)
    },
  },
  beforeMount() {
    this.showAlert()
  },
  data() {
    return {
      userId: sessionStorage.getItem('userId'),
      roleName: sessionStorage.getItem('roleName'),
    }
  },
}
```

**Reegel:** kui koodis pole viidet HTML elemendile (nt `$refs`), on `beforeMount` kiirem valik. Kui on vaja `$refs` kaudu elementi puudutada, tuleb kasutada `mounted`, muidu tuleb viga ("element pole veel olemas").

### `$refs`: viide otse HTML elemendile (harva vajalik)

Template'is saab elemendile panna `ref` atribuudi, ja skriptis viidata sellele `this.$refs.nimi` kaudu:

```html
<div ref="useridShowBox">userId: x</div>
```

```js
this.$refs.useridShowBox  // viide otse sellele DOM elemendile
```

**Oluline:** `$refs` kasutamist tuleks vältida igapäevaselt — Vue eesmärk on, et andmete kaudu (reaktiivsus) mõjutad kuvatavat sisu, mitte otse DOM-i käperdades. `$refs` on vajalik ainult üksikutel eranditel (nt faili valiku input'i visuaalse oleku tühistamiseks).

### Päriselu analoogia

`beforeMount` vs `mounted` on nagu vahe köögi ettevalmistamise ja köögi kasutamise vahel — `beforeMount` on hetk, kui köök pole veel sisse seatud (lauad-toolid pole kohal), `mounted` on hetk, kui kõik on juba paigas ja saab kokkama hakata.

## Turvalisus: paroolid, plain text ja disclaimer — `1:46:58` {#turvalisus}

### Selgitus

Õpetaja rõhutas olulist **disclaimer'it** (hoiatust): õppeprojektis saadetakse paroolid hetkel **plain text** (krüptimata tekstina) kujul, mis on **päriselus lubamatu**. Reaalses tootmiskeskkonnas peavad paroolid olema alati krüptitud ja sisselogimisel kasutatakse sessioone/tokene, mitte paroolide otsest edastamist.

**Oluline juhis:** kui keegi (nt kogenud arendaja) aitab õpilasel projektiga, tuleks talle kohe öelda: *"see logimissüsteem pole tehtud päris turvastandardite järgi — see on õppeharjutus"*, et vältida arusaamatust või ehmatust.

Lisaks räägiti üldisest turvateadlikkusest — nt vältida avalikku WiFi-t tundlike andmete sisestamisel, mitte panna oma kasutajakontosid tundmatutesse USB-portidesse jne.

### Päriselu analoogia

Plain text parooli saatmine on nagu kirjutada oma pangaparool postkaardile ja saata see läbi tavaposti — igaüks, kes kaarti näeb (võrguliiklust pealt kuulab), näeb parooli otse.
