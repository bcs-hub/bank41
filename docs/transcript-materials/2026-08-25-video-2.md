## Git: kuidas õpetajale kiirelt järgi jõuda — `0:00:11` {#git-jargi-joudmine}

Tund algab praktilise harjutusega: kuidas kiirelt "järgi jõuda" õpetaja koodiseisu, kui sul endal on pooleliolevaid muudatusi.

### Selgitus

Kui tahad võtta õpetaja töö täpselt samast kohast, kus tema parasjagu on, peab sinu Git tööseis olema **puhas** — ei tohi olla lahtiseid (commitimata) muudatusi ega jälgimata (untracked) faile. Kui need on olemas, tekib haru vahetamisel konflikt, sest Git ei tea, mida nende muudatustega peale hakata.

Selle jaoks on kaks võimalust:
1. **Commiti oma muudatused ära** oma harusse (kui tahad neid hiljem kätte saada)
2. **Viska muudatused minema** (Rollback), kui need pole tähtsad

### Skeem

```
Sinu töölaud (Working Directory)
        |
        v
  On lahtisi muudatusi? ---- JAH ----> Rollback (kustuta) VÕI Commit (salvesta)
        |
        NO
        v
  Fetch (tõmba uusim info õpetaja harust)
        |
        v
  Checkout Remote/õpetaja -> New Branch (nt "V-2")
        |
        v
  Nüüd oled täpselt õpetajaga samas kohas
```

### Koodinäide (kontseptuaalne käsujada)

```bash
# 1. Kui on lahtisi muudatusi, mida ei taha alles hoida:
#    IntelliJ's: paremklõps failidel -> Rollback

# 2. Tõmba uusim info serverist
git fetch

# 3. Võta uus haru otse remote'i (õpetaja) harust, mitte lokaalsest
git checkout -b V-2 origin/õpetaja
```

### Päriselu analoogia

Mõtle sellele nagu jagatud Google Docs dokumendile: kui sul on pooleli lause, mida keegi teine samal ajal üle kirjutab, tekib segadus. Enne kui "hüppad" kellegi teise versiooni juurde, pead oma pooleliolev töö kas ära salvestama (kuskile mujale) või lihtsalt kustutama, et vahetus saaks sujuvalt toimuda.

## Haru nimetamise tavad ja tiketinumbrid — `0:04:35` {#haru-nimetamine}

### Selgitus

Reaalses arenduses saab iga töölõik (task/ticket) unikaalse numbri (nt `FEB-7`, `VEB-16`). Haru nimeks pannakse tavaliselt just see number, sest:

- **Haru nimi peab olema unikaalne** repositooriumis — kaks sama nimega haru ei saa eksisteerida korraga
- **Tiketi number ei kordu kunagi** — isegi kui tegemist on sarnase teemaga, tehakse ikka uus number, mitte ei kasutata vana uuesti
- Kui on vaja viidata varasemale sarnasele tööle, tehakse seda tekstiviitena tiketi sees, mitte number ise ei muutu

### Päriselu analoogia

Tiketinumber on nagu isikukood — igaühel oma unikaalne number, mida ei anta kunagi teisele inimesele uuesti, isegi kui esimene inimene "kaob" (näiteks tiket suletakse).

## IntelliJ: Rainbow Brackets ja koodi sugulussuhted — `0:18:38` {#rainbow-brackets}

### Selgitus

**Rainbow Brackets** on IntelliJ plugin (Settings → Plugins → otsi "Rainbow"), mis värvib koodis sulge ja HTML tage vastavalt sellele, kuidas need üksteise sees paiknevad. See aitab visuaalselt näha, kust mingi element **algab** ja kust **lõpeb**, ning mõista elementide **hierarhiat** (sugulussuhteid):

- **Parent** (vanem) — element, mille sees teine element asub
- **Child** (laps) — element, mis asub teise elemendi sees
- **Sibling** (õde-vend) — kaks elementi, kellel on sama parent

### Skeem

```html
<table>              <-- parent kõigele allpool
  <tr>                <-- table'i laps (child)
    <td>...</td>      <-- tr laps, table'i lapselaps (grandchild)
    <td>...</td>      <-- eelmise td "õde-vend" (sibling)
  </tr>
</table>
```

### Päriselu analoogia

Nagu perekonnapuu: vanem (parent), laps (child), lapselaps (grandchild) ja õed-vennad (siblings, kellel on ühised vanemad). HTML struktuur järgib täpselt sama loogikat.

## HTML vormielemendid: input, label, select — `0:31:38` {#vormielemendid}

### Selgitus

Vormi loomisel kasutatakse mitmesuguseid `input` tüüpe ja neile "siltisid" (label). Koodinäide meie panga projektist (`frontend/index.html`) näitab tüüpilist vormi struktuuri:

```html
<label for="firstName">Eesnimi</label>
<input type="text" id="firstName">
```

- `label` element on **kahe tagiga element**, mis annab kastile visuaalse sildi
- `for="firstName"` atribuut label'is peab kattuma inputi `id`-ga — see seob nad **programmiliselt**, mitte ainult visuaalselt
- See seos on tähtis ka **ligipääsetavuse (accessibility)** jaoks: ekraanilugejaga (screen reader) kasutaja jaoks loeb rakendus ette, milline silt kuulub millisele kastile

`input` elemendil on `type` atribuut, mis muudab kasti käitumist täielikult:

| `type` väärtus | Käitumine |
|---|---|
| `text` | tavaline tekstikast |
| `number` | ainult numbrid |
| `password` | tähed peidetakse tärnidega |
| `date` | kuupäevavalija |
| `checkbox` | linnuke |
| `radio` | ümmargune valik |
| `file` | failivalija |

### Koodinäide (projektist, `frontend/index.html:68-77`)

```html
<label for="firstName">Eesnimi</label>
<input type="text" id="firstName">
<br>

<label for="lastName">Perekonnanimi</label>
<input type="text" id="lastName" placeholder="Tamm">
<br>

<label for="age">Vanus</label>
<input type="number" id="age" >
```

### Tähtsad atribuudid

- **`placeholder`** — hall vihjetekst kastis, mis **ei ole päris sisu** (kui klikid kasti, on see ikkagi tühi)
- **`value`** — paneb kastisse **päris teksti**, mis on juba sees (erinevalt placeholder'ist)

### Päriselu analoogia

`placeholder` on nagu hallis kirjas tekst paberankeedil ("Nt: Jaan Tamm"), mis kaob, kui hakkad ise kirjutama — see pole osa vastusest, vaid ainult vihje.

## Andmebaasi ID-d ja rippmenüü väärtused — `0:46:39` {#andmebaasi-id}

### Selgitus

`select` / `option` element loob rippmenüü, kus igal valikul on kaks poolt:
- **Nähtav tekst** (label) — see, mida kasutaja ekraanil näeb
- **`value`** — tegelik väärtus, mis on "taustal" ja mida programm hiljem kasutab

```html
<select>
    <option value="0" disabled selected>--linn--</option>
    <option value="2">Tallinn</option>
    <option value="3">Tartu</option>
    <option value="1">Viljandi</option>
</select>
```

- **`disabled`** esimesel valikul tähendab, et seda ei saa valida — kasutatakse vihjena ("vali linn")
- **`selected`** tähendab, et see valik on vaikimisi näidatud
- Väärtused (`0`, `1`, `2`, `3`) ei pea olema järjestikused — need vastavad tegelikult **andmebaasi tabeli ridade ID-dele**

### Andmebaasi ID-de põhiprintsiip

Relatsioonilises andmebaasis saab iga uus rida oma unikaalse ID, mis:
- Kunagi ei kordu (isegi kui rida kustutatakse, seda numbrit enam ei taaskasutata)
- Jääb selle reaga seotuks kuni "surmani" (kustutamiseni)

See on põhjus, miks `value` väärtused rippmenüüs võivad tunduda suvalised — need viitavad päris andmebaasi ridadele.

### Päriselu analoogia

Nagu isikukood: igal inimesel oma number, mida ei anta kunagi teisele, isegi kui esimene inimene "lahkub süsteemist".

## Radio nupud vs checkbox — `0:58:55` {#radio-checkbox}

### Selgitus

- **Radio nupud**: saad valida ainult **ühe** mitmest valikust
- **Checkbox**: saad valida **mitu** korraga

Selleks, et radio nupud "teaksid", et nad kuuluvad samasse gruppi (ja üksteist välistavad), peab neil olema **sama `name` atribuut**:

```html
<input type="radio" name="gender">
<label for="">Mees</label>
<br>
<input type="radio" name="gender">
<label for="">Naine</label>
```

Kui mõlemal radio nupul on `name="gender"`, saab kasutaja valida ainult ühe neist — valides "Naine" tühistub automaatselt "Mees" valik.

### Päriselu analoogia

Radio nupud toimivad nagu vanaaegse raadio jaamanupud — vajutades ühe nupu sisse, hüppab eelmine automaatselt välja. Checkbox on aga nagu poe ostunimekiri — saad linnutada nii palju ridu, kui tahad.

## Lingid, checkbox ja tekstisisesed elemendid (span) — `1:06:51` {#lingid-checkbox}

### Selgitus

Link luuakse `<a>` (anchor) elemendiga koos `href` atribuudiga (kuhu link viib):

```html
<a href="/tingimused.html" target="_blank">tingimustega</a>
```

- **`href`** — sihtkoht (URL või fail projektis)

```html

<span>Nõustun kõigi</span>
<a href="/tingimused.html" target="_blank">tingimustega</a>
```

### Päriselu analoogia

`<span>` on nagu läbipaistev pakend — see hoiab sisu koos, aga ei muuda visuaalselt midagi, erinevalt `<p>`-st, mis on nagu eraldi karp, mis alati võtab terve rea.

## div element ja HTML hierarhia — `1:53:24` {#div-element}

### Selgitus

`<div>` on **täiesti neutraalne "sisuala" element** — ise ei tee midagi nähtavat, aga on mõeldud selleks, et saaksid sellest ise midagi "meisterdada" (nt tabeli, kaardi, sektsiooni). Divid saavad üksteise sees olla samamoodi nagu HTML elemendid üldse — luues parent/child/sibling hierarhia.

Kui divile lisada CSS stiil (nt taustavärv), muutub selle **nähtavaks piirjooneks**, ja siis on selgelt näha, kuidas divid üksteise sees paiknevad.

### Skeem

```
<div> (tabel)
  <div> (rida)
    <div>(veerg 1)</div>
    <div>(veerg 2)</div>
  </div>
</div>
```

### Päriselu analoogia

`div` on nagu tühi papikast — ise ei ütle midagi selle kohta, mis sees on, aga saad seda kasutada mistahes sisu jaoks ja kaste üksteise sisse panna.

## CSS sissejuhatus: mis see on ja miks seda kasutatakse — `2:01:48` {#css-sissejuhatus}

### Selgitus

**CSS** = **C**ascading **S**tyle **S**heets (kaskaadstiililehed). CSS-i kasutatakse HTML dokumendi **välimuse** kirjeldamiseks — paigutus, värvid, tüpograafia jne.

Peamine eesmärk: **eraldada sisu (HTML) esitlusest (CSS)**. See on üldine programmeerimise põhimõte — hoia erinevad asjad eraldi kohtades, mitte koos.

**Eelised:**
- Parem hooldatavus
- Taaskasutatavus
- Ligipääsetavus
- Väiksem failimaht (kiirem laadimine)

### Päriselu analoogia

Mõtle sellele nagu maja ehitusele: konstruktsioon (kandekonstruktsioonid, seinad — HTML) ja sisekujundus (värvid, mööbel — CSS) on eraldi otsused. Saad muuta värve, ilma et peaksid seinu ümber ehitama.

## CSS kolm rakendamisviisi: reasisene, head-sektsioon, eraldi fail — `2:02:54` {#css-kolm-viisi}

### Selgitus

Stiili saab rakendada kolmel viisil, ajaloolises järjekorras:

1. **Reasisene stiil (inline style)** — `style` atribuut otse elemendil
2. **`<head>` sektsiooni stiiliplokk** — `<style>` element lehe päises, kehtib kogu lehele
3. **Eraldi CSS fail** — parim praktika, ühendatud `<link>` elemendiga

### Koodinäide (variant 1 — reasisene, projektist `frontend/index.html:18`)

```html
<p>Siin on meie <span style="color: red">90'ndate stiilis</span> pank.</p>
```

### Koodinäide (variant 2 — head sektsioonis)

```html
<head>
    <style>
        body {
            background-color: violet;
        }
    </style>
</head>
```

### Koodinäide (variant 3 — eraldi fail)

```html
<head>
    <link rel="stylesheet" href="style.css">
</head>
```

### Päriselu analoogia

Reasisene stiil on nagu ühe konkreetse eseme värvimine käsitsi; head-sektsiooni stiil on nagu terve toa värvimine korraga; eraldi CSS fail on nagu värvikataloog, mida saab kasutada mitmes toas (lehel) korraga.

## CSS selektorid ja täpsuse (specificity) reeglid — `2:07:26` {#css-selektorid}

### Selgitus

CSS "otsib üles" HTML elemendid ja rakendab neile stiili. On kolm peamist **selektori tüüpi**, järjestatud täpsuse järgi (kõige ebatäpsemast kõige täpsemani):

1. **Elemenditüüp** (nt `h4`) — mõjutab **kõiki** selle tüübi elemente lehel
2. **Klass** (`.klassinimi`) — mõjutab kõiki elemente, kellele see klass on antud
3. **ID** (`#idnimi`) — mõjutab **ainult ühte** konkreetset elementi (ID peaks olema unikaalne)

**Täpsuse reegel:** kui mitu selektorit sobivad samale elemendile, võidab **täpsem** (ID > klass > elemenditüüp). Kui kaks sama täpsuse selektorit satuvad kokku, võidab see, mis on **koodis hiljem** (allpool).

### Skeem

```
elemenditüüp (h4)        <- kõige ebatäpsem, mõjutab kõiki h4-sid
      ↓
klass (.awesomePurple)   <- mõjutab kõiki, kellel see klass on
      ↓
ID (#hourCustomers)      <- kõige täpsem, mõjutab ainult üht elementi
```

### Koodinäide (projektist, `frontend/index.html:31`)

```html
<h4 class="awesomeGreen  awesomePurple  ">Meie kliendid</h4>
```

```css
h4 {
    border-style: dashed;
}
.awesomeGreen {
    background-color: green;
}
.awesomePurple {
    background-color: purple;
}
```

Sellel elemendil on **mõlemad klassid** korraga — võidab see, mis on CSS failis **hiljem kirjutatud** (siin: `awesomePurple`, kuna see tuli teisena).

### Päriselu analoogia

Mõtle sellele nagu värvikihtidele: kui värvid mitu kihti üksteise peale, jääb peale viimane kiht (kõige uuem värv), aga ainult neis kohtades, kus see tegelikult kaeti — vanem kiht jääb nähtavaks seal, kus uus kiht seda ei kata.

## !important ja miks seda vältida — `2:20:20` {#important}

### Selgitus

`!important` on CSS-i "erakorraline volitus", mis sõidab üle **kõikidest** tavalistest täpsuse reeglitest (isegi ID-st):

```css
#hourCustomers {
    background-color: green !important;
}
```

**Miks seda vältida:**
- Kui kõik kasutavad `!important`, kaotab see oma mõtte ("important'ist ei ole enam veel important'imat")
- Raske hiljem üle kirjutada — muudab koodi raskesti hallatavaks
- Peaks kasutama ainult siis, kui on **hädavajalik** üle sõita mõne raamistiku (nt Bootstrap) vaikeväärtusest

### Päriselu analoogia

`!important` on nagu punane "KIIRE!" märge kirja peal — kui iga kiri on "kiire", kaotab see märge oma mõtte ja tähtsad kirjad upuvad ära.

## Eraldi CSS fail ja selle eelised — `2:23:12` {#eraldi-css-fail}

### Selgitus

Kui stiil paikneb eraldi `.css` failis, ei ole HTML fail "teadlik" stiilidest — vaja on `<link>` elementi, mis viitab CSS failile:

```html
<link rel="stylesheet" href="style.css">
```

**Eelised:**
- **Taaskasutatavus** — sama stiilifail saab kehtida mitmele HTML lehele korraga
- **Väiksem koodimaht** — kiirem laadimine (eriti mobiilil ja aeglasel internetil)
- **Kergem hooldada** — muudatuse tegemiseks piisab ühest kohast, mitte igalt lehelt eraldi otsimisest

### Päriselu analoogia

Nagu kokkuvõttev retseptiraamat, kuhu on kirjutatud üks retsept, mida saab kasutada mitmes köögis (lehel) korraga — kui retsepti muudad, muutub see kõikjal, kus seda kasutatakse.

## Bootstrap: valmis CSS raamistik — `2:37:29` {#bootstrap}

### Selgitus

**Bootstrap** on populaarne, valmis CSS/JS raamistik, mis pakub valmis klasse (nt tabelite, nuppude, vormide jaoks), et kiirelt kujundada veebilehte ilma, et peaks ise kõike CSS-i kirjutama.

```html
<table class="table table-dark table-hover">
```

- `table` — põhiline tabeli stiil
- `table-dark` — tume teema
- `table-hover` — rea esiletõstmine hiirega üle liikudes

**Riskid väliste teenuste kasutamisel:** kui CSS/JS laaditakse välise CDN-i pealt (mitte oma serverist), tekib sõltuvus välisest teenusest — kui see server ei tööta, näeb rakendus stiilideta (katki) välja. Suuremad ettevõtted (nt pangad) tavaliselt tõmbavad sellised sõltuvused **oma serverisse** (või kasutavad projekti sõltuvuste haldust, nt npm), mitte ei viita otse välisele CDN-ile.

### Koodinäide (projektist, `frontend/index.html:7-9`)

```html
<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css" rel="stylesheet">
<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js"></script>
```

### Päriselu analoogia

Bootstrap on nagu valmis mööbel poest (IKEA) — kiire ja odav lahendus, aga kõigil on sarnane välimus. Custom CSS on nagu tellimustööna valmistatud mööbel — unikaalne, aga kallim ja aeganõudvam.

## JavaScript ja Java: muutujad kui sildikesed — `2:50:37` {#muutujad}

### Selgitus

Tund lõpeb sissejuhatusega järgmise päeva teemasse — JavaScript ja programmeerimine. Õpetaja soovitab mõelda **muutujatest kui "sildikestest"** (mitte "ümbrikutest", nagu vanasti õpetati):

- **Silt (label/nimi)** — muutuja nimi, millega saab andmetele viidata
- **Objekt/väärtus** — see, mis on sildi "taga"
- Silt ja objekt on **kaks erinevat asja** — silt on nagu paberilipik, objekt on päris "asi", millele see viitab

**JavaScript vs Java:** JavaScripti nimi tuli sellest, et Java oli juba populaarne, kui JS loodi (marketingivõte, mitte tehniline seos). Peamine erinevus:

| | Java | JavaScript |
|---|---|---|
| Tüübikontroll | tüübikindel (type-safe) | vaikimisi tüübitundetu |
| Käivitamine | kompileeritakse enne käivitamist | interpreteeritakse (jooksutatakse "lennult") |

### Koodinäide (kontseptuaalne)

```javascript
let student = "Rain"   // "student" on silt, "Rain" on objekt (väärtus) selle taga
```

### Päriselu analoogia

Muutuja on nagu nimesilt kohvritel lennujaamas — silt (nimi) jääb samaks, aga kohver (objekt/väärtus) selle taga võib aja jooksul vahetuda (nt kui täidad kohvri teistsuguse sisuga).
