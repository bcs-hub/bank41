## Valideerimine `if`–`else if` ahelaga — `0:01:10` {#if-else-if}

### Selgitus

Valideerimine tähendab kontrollimist, kas vormi andmed vastavad reeglitele. Videos soovitakse kuvada korraga ainult esimene leitud viga. Selleks sobib `if`–`else if` ahel: kui esimene tingimus on tõene, järgmisi harusid enam ei kontrollita.

Eraldi `if` lausete puhul võiks mitu reeglit korraga käivituda ning hilisem teade kirjutaks varasema üle. `else if` teeb harud üksteist välistavaks.

### Koodinäide (`frontend/src/views/LocationView.vue`)

```js
checkFormForErrors() {
  if (this.location.cityId === 0) {
    this.errorMessage = 'Vali linn'
  } else if (this.location.locationName === '') {
    this.errorMessage = 'Lisa asukoha nimi'
  } else if (this.location.numberOfAtms < 1) {
    this.errorMessage = 'Automaatide arv peab olema vähemalt 1'
  } else if (!this.transactionTypeIsSelected()) {
    this.errorMessage = 'Vali vähemalt üks ATM teenus'
  }
},
```

### Skeem

```text
Kas linn puudub? ──jah──> "Vali linn" ja ahel lõpeb
       │ ei
       ▼
Kas nimi puudub? ──jah──> "Lisa asukoha nimi" ja ahel lõpeb
       │ ei
       ▼
Kas arv < 1? ─────jah──> vastav veateade ja ahel lõpeb
       │ ei
       ▼
Kas teenus puudub? ─jah─> vastav veateade
```

### Päriselu analoogia

See on nagu kontrollnimekiri, kus parandatakse korraga esimest leitud probleemi. Alles järgmisel katsel jõutakse järgmise punktini.

## Asukoha nime ja automaatide arvu kontroll — `0:03:43` {#valjade-kontroll}

### Selgitus

Asukoha nime algväärtus on tühi string `''`. Seega tähendab võrdlus `locationName === ''`, et kasutaja pole nime sisestanud.

Automaatide arv peab olema vähemalt üks. Kontroll `numberOfAtms < 1` püüab kinni nulli ja negatiivsed arvud. Videos avastatakse ka oluline vormikäitumine: kui number-input tühjaks teha ja väärtus teisendada `Number(...)` abil, muutub tühi string arvuks `0`.

### Koodinäide

```js
if (this.location.locationName === '') {
  this.errorMessage = 'Lisa asukoha nimi'
} else if (this.location.numberOfAtms < 1) {
  this.errorMessage = 'Automaatide arv peab olema vähemalt 1'
}
```

Tugevamas lahenduses tasub tühimärgid enne kontrolli eemaldada:

```js
if (this.location.locationName.trim() === '') {
  this.errorMessage = 'Lisa asukoha nimi'
}
```

### Päriselu analoogia

Tühikutest koosnev nimi on nagu ankeedi lahtrisse tehtud nähtamatu kriips: tehniliselt on midagi kirjutatud, kuid sisulist vastust ei ole.

## Parent’i juhitud sisend ja andmevoog mõlemas suunas — `0:15:35` {#parent-juhitud-sisend}

### Selgitus

Eelmises videos liikusid sisendite muudatused custom event’idega child’ist parent’i. See ühesuunaline tee ei ole vormi lähtestamiseks piisav. Pärast edukat lisamist muudab parent mudeli algseisu, kuid child’i input peab sellest muudatusest samuti teada saama.

Seetõttu kasutatakse kahte suunda:

- props viib väärtuse parent’ist child’i;
- custom event viib kasutaja muudatuse child’ist parent’i.

See ei ole kaks sõltumatut andmeallikat. Tõeallikas on endiselt `LocationView.location`; child kuvab props’i ja teatab muudatusest.

### Skeem

```text
LocationView.locationName
          │ props alla
          ▼
LocationNameInput :value
          │ kasutaja kirjutab
          │ custom event üles
          ▼
LocationView uuendab locationName’i
```

### Päriselu analoogia

Parent on keskne register. Child saab registrist kehtiva väärtuse ja saadab sinna muudatusettepaneku, kuid ei pea ise eraldi koopiat tõeallikana.

## Sisendite algväärtuste edastamine props’idega — `0:18:11` {#sisendite-propsid}

### Selgitus

`LocationForm` saab terve `location` objekti props’ina. Sealt antakse igale väiksemale sisendkomponendile ainult vajalik väli. `:value` seob HTML-inputi kuvatava väärtuse props’iga.

### Koodinäide (`frontend/src/components/LocationForm.vue`)

```vue
<LocationNameInput
  :location-name="location.locationName"
  @event-new-location-name-input="
    $emit('event-new-location-name-input', $event)
  "
/>

<NumberOfAtmsInput
  :number-of-atms="location.numberOfAtms"
  @event-new-number-of-atms-input="
    $emit('event-new-number-of-atms-input', $event)
  "
/>
```

Child-komponendis:

```vue
<script>
export default {
  props: {
    locationName: String,
  },
}
</script>

<template>
  <input
    :value="locationName"
    @input="$emit('event-new-location-name-input', $event.target.value)"
  />
</template>
```

`numberOfAtms` puhul teisendatakse sündmuse väärtus kohe numbriks:

```vue
@input="$emit('event-new-number-of-atms-input', Number($event.target.value))"
```

## Vähemalt ühe teenuseliigi kontrollimine — `0:34:55` {#teenuseliigi-kontroll}

### Selgitus

Asukoha `transactionTypes` on objektide massiiv. Igal objektil on `isAvailable` Boolean-väli. Ärireegel ütleb, et vähemalt ühe elemendi väärtus peab olema `true`.

Kontrolli mõte on:

1. käi massiivi elemendid järjest läbi;
2. kui leiad ühe `isAvailable === true` elemendi, on nõue täidetud;
3. kui tsükkel lõpeb vastet leidmata, ei ole ühtegi teenust valitud.

### Näidisandmed

```js
transactionTypes: [
  { transactionTypeId: 1, isAvailable: false },
  { transactionTypeId: 2, isAvailable: true },
  { transactionTypeId: 3, isAvailable: false },
]
```

Siin piisab teisest objektist, et tulemus oleks `true`.

## `for...of`, varajane `return` ja Boolean-meetod — `0:42:19` {#for-of-ja-return}

### Selgitus

Kontroll eraldatakse meetodisse `transactionTypeIsSelected()`, mis vastab ühe selge `true`/`false` väärtusega. `for...of` annab igal tsüklil massiivi järgmise elemendi ehk siin terve transaction type’i objekti.

Kui sobiv element leitakse, lõpetab `return true` kohe nii tsükli kui ka meetodi. Ülejäänud elemente pole vaja kontrollida. `return false` asub pärast tsüklit ja käivitub ainult siis, kui ükski element ei sobinud.

### Koodinäide

```js
transactionTypeIsSelected() {
  for (const transactionType of this.location.transactionTypes) {
    if (transactionType.isAvailable) {
      return true
    }
  }

  return false
},
```

### Skeem

```text
element 1: false → jätka
element 2: true  → return true → meetod lõpeb
element 3:       → selleni ei jõuta

Kui kõik olid false → tsükkel lõpeb → return false
```

### Päriselu analoogia

Kui otsid sahtlist vähemalt ühte võtit, lõpetad otsimise kohe esimese võtme leidmisel. Kõigi ülejäänud esemete kontrollimine ei anna enam midagi juurde.

## Eitusoperaator `!` veaolukorra väljendamisel — `0:52:55` {#eitusoperaator}

### Selgitus

Meetod `transactionTypeIsSelected()` ütleb positiivselt, kas vähemalt üks teenus on valitud. Valideerimine otsib aga vastupidist olukorda: viga on siis, kui ühtegi teenust pole valitud.

Hüüumärk `!` pöörab Boolean-väärtuse ümber:

```text
true  → !true  → false
false → !false → true
```

### Koodinäide

```js
// Loe: kui transaction type EI ole valitud, kuva viga.
if (!this.transactionTypeIsSelected()) {
  this.errorMessage = 'Vali vähemalt üks ATM teenus'
}
```

Meetodi nimi jääb positiivseks ja on seepärast ka teistes olukordades lihtsamini kasutatav.

## Valideerimisloogika eraldamine meetoditesse — `0:59:35` {#valideerimise-refaktor}

### Selgitus

Kui kogu kontrollikood jääb `addLocation()` meetodisse, kaob põhitegevus detailide vahele. Refaktorimise järel loeb meetod nagu lühike tegevuskava:

1. puhasta vanad teated;
2. kontrolli vormi;
3. saada päring ainult siis, kui viga ei ole.

### Koodinäide

```js
addLocation() {
  this.resetSuccessMessage()
  this.resetErrorMessage()
  this.checkFormForErrors()

  if (this.errorMessageIsEmpty()) {
    // POST-päring
  }
},

errorMessageIsEmpty() {
  return this.errorMessage === ''
},
```

Meetodi nimi peidab tehnilise võrdluse ja väljendab kavatsust. See on kasulik „raamatu lugemise” põhimõte: kõrgema taseme meetod näitab peatükke, abimeetodid sisaldavad detaile.

## POST-päringu käivitamine ainult korrektse vormiga — `1:12:13` {#post-paringu-kaivitamine}

### Selgitus

Pärast valideerimist kontrollitakse `errorMessage` väärtust. Kui see on endiselt tühi, võib keskse `location` objekti backend’ile saata. Axios tagastab Promise’i:

- `.then(...)` käsitleb edukat vastust;
- `.catch(...)` käsitleb viga.

### Koodinäide (`frontend/src/views/LocationView.vue`)

```js
if (this.errorMessageIsEmpty()) {
  LocationService.postAtmLocationRequest(this.location)
    .then(() => this.handleAddLocationResponse())
    .catch((error) => this.handleAddLocationErrorResponse(error))
}
```

Service-kihis:

```js
postAtmLocationRequest(location) {
  return axios.post('/api/atm/locations', location)
},
```

### Skeem

```text
checkFormForErrors()
        │
        ▼
errorMessage === '' ?
   ├─ ei  → näita viga, päringut ei saadeta
   └─ jah → POST → then või catch
```

## Eduka vastuse käsitlemine ja `AlertSuccess` — `1:22:33` {#edukas-vastus}

### Selgitus

API edukas POST-vastus ei pea tingimata sisulist response body’t tagastama. Rakendus teab juba, millise asukoha ta saatis. Edu korral tuleb kasutajale näidata kinnitust ja vorm lähtestada.

`AlertSuccess` töötab samal põhimõttel nagu `AlertDanger`: tühi teade ei renderdu, sisuga teade kuvatakse. Erinevus on Bootstrapi roheline `alert-success` kujundus.

### Koodinäide (`frontend/src/components/AlertSuccess.vue`)

```vue
<script>
export default {
  props: {
    successMessage: String,
  },
}
</script>

<template>
  <div v-if="successMessage !== ''" class="alert alert-success" role="alert">
    {{ successMessage }}
  </div>
</template>
```

Kasutamine vaates:

```vue
<AlertSuccess :success-message="successMessage" />
<AlertDanger :error-message="errorMessage" />
```

## `for...in` ja `for...of` vea debugimine — `1:57:57` {#for-in-vs-for-of}

### Selgitus

Tunnis ilmneb viga: kõik checkbox’id on valitud, kuid valideerimine ütleb endiselt, et teenus puudub. Brauseri debugger näitab, et tsükli muutuja ei sisalda objekti, vaid väärtust `"0"`.

Põhjus on `for...in` ja `for...of` erinevus:

- `for...in` käib massiivi võtmed ehk indeksid läbi (`"0"`, `"1"`, `"2"`);
- `for...of` käib massiivi väärtused ehk objektid läbi.

### Koodinäide

```js
const services = [
  { isAvailable: false },
  { isAvailable: true },
]

for (const index in services) {
  console.log(index) // "0", seejärel "1"
}

for (const service of services) {
  console.log(service) // objekt, näiteks { isAvailable: false }
}
```

Õige kontroll:

```js
for (const transactionType of this.location.transactionTypes) {
  if (transactionType.isAvailable) {
    return true
  }
}
```

### Debugimise käik

```text
1. Korda viga brauseris.
2. Pane breakpoint tsüklisse.
3. Vaata massiivi — kolm objekti on olemas.
4. Vaata tsüklimuutujat — seal on "0", mitte objekt.
5. Kontrolli tsükli süntaksit.
6. Asenda in → of ja proovi uuesti.
```

## Dünaamiliste valikute uuesti laadimine — `2:07:03` {#valikute-uuesti-laadimine}

Transaction type’id pärinevad API-st. Nende algseisu käsitsi dubleerimine `resetAllFields()` meetodis seoks frontendi serveri andmetega ja tekitaks kaks tõeallikat. Selle asemel kutsutakse uuesti juba olemasolevat laadimismeetodit.

## POST-päringu veavastuse struktuur — `2:25:35` {#post-veavastus}

### Selgitus

Axios annab `.catch(...)` harule `error` objekti. HTTP-vastuse andmed asuvad ühe kihi sügavamal:

```text
error
└─ response
   ├─ status
   └─ data
      ├─ message
      └─ errorCode
```

Projekt kopeerib `error.response.data` lihtsamasse `errorResponse` mudelisse. Seejärel saab staatust lugeda algsest response’ist ning ärilist veakoodi ja teadet data-objektist.

### Koodinäide

```js
errorResponse: {
  message: '',
  errorCode: '',
},
```

```js
handleAddLocationErrorResponse(error) {
  this.errorResponse = error.response.data

  // Edasine otsus sõltub staatusest ja errorCode’ist.
},
```

## Tuntud ärivea kuvamine ja tundmatu vea suunamine — `2:32:47` {#vea-kasitlemine}

### Selgitus

Frontend oskab konkreetselt käsitleda olukorda, kus sama asukoht on juba olemas. Selle tunnuseks on korraga:

- HTTP staatus `403`;
- rakenduse veakood `LOCATION_UNAVAILABLE`.

Kasutajale kuvatav tekst võetakse backend’i `message` väljast. Seda ei kirjutata frontend’i teist korda, sest backend teab konkreetse ärivea sisu. Kõik ootamatud vead suunatakse üldisele veavaatele.

### Koodinäide

```js
handleAddLocationErrorResponse(error) {
  this.errorResponse = error.response.data

  if (
    error.response.status === 403 &&
    this.errorResponse.errorCode === 'LOCATION_UNAVAILABLE'
  ) {
    this.errorMessage = this.errorResponse.message
  } else {
    NavigationService.navigateToErrorView()
  }
},
```

### Skeem

```text
POST ebaõnnestub
       │
       ▼
status 403 + LOCATION_UNAVAILABLE?
   ├─ jah → näita backend’i message’it vormil
   └─ ei  → navigateToErrorView()
```

## Lähtestatud väärtuste tagasi saatmine child’idele — `2:46:57` {#vaartused-tagasi-childidele}

### Selgitus

Parent’i mudeli lähtestamisest on ekraanil kasu ainult siis, kui child-komponendid kuvavad parent’ilt saadud props’e. Videos viiakse see lõpuni linnavaliku näitel.

`LocationView` annab `location` objekti `LocationForm` komponendile. Vorm annab sealt `cityId` edasi `CitiesDropdown` komponendile. Dropdown seob väärtuse `<select>` elemendiga.

### Koodinäide (`frontend/src/components/LocationForm.vue`)

```vue
<CitiesDropdown
  :city-id="location.cityId"
  :cities="cities"
  @event-new-city-selected="$emit('event-new-city-selected', $event)"
/>
```

`CitiesDropdown.vue`:

```vue
<script>
export default {
  props: {
    cityId: {
      type: Number,
      default: 0,
    },
    cities: Array,
  },
}
</script>

<template>
  <select
    :value="cityId"
    @change="$emit('event-new-city-selected', Number($event.target.value))"
  >
    <option :value="0">Kõik linnad</option>
    <option v-for="city in cities" :key="city.cityId" :value="city.cityId">
      {{ city.cityName }}
    </option>
  </select>
</template>
```

### Lõplik andmevoog

```text
Kasutaja muudab välja
  → child emit’ib väärtuse üles
  → LocationView uuendab location mudelit
  → POST saadab sama mudeli backend’i
  → edu korral resetAllFields()
  → uued algväärtused voolavad props’idega alla
  → kõik sisendid kuvavad taas algseisu
```

## Kokkuvõte

Video viib asukoha lisamise põhivoo tervikuks: vorm valideeritakse, korrektne `location` objekt saadetakse backend’i ning kasutaja saab edu- või veateate. Edu korral lähtestatakse keskne mudel ja väärtused voolavad props’idega tagasi kõigisse sisendkomponentidesse.

Oluline praktiline õppetund on süstemaatiline debugimine. `for...in` andis objektide asemel massiivi indeksid; breakpoint ja muutujate tegelike väärtuste vaatamine näitas põhjust ning `for...of` taastas korrektse valideerimise.
