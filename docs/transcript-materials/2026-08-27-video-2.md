## LoginView loomine ja API versioonid — `0:00:00` {#loginview}

### Selgitus

Tund algas uue vaate — **LoginView** — loomisega, samamoodi nagu eelmises videos kirjeldatud sammudega (branch → komponent → route → nav link). Lisaks tuli jutuks, miks API teele lisatakse versiooninumber, nt `/api/v1/login`.

**Miks versioon URL-is?** Kui API muutub tulevikus (nt `username` asemel hakatakse nõudma `email`), ei tohi vanad kliendid (nt mobiilirakendus, mida inimesed pole uuendanud) katki minna. Uus versioon (`/api/v2/login`) käib paralleelselt vana kõrval, kuni kõik on üle kolinud.

### Skeem

```
/api/v1/login   ← praegune versioon, kasutab { username, password }
/api/v2/login   ← tulevikus, kui kuju muutub, nt { email, password }
```

### Päriselu analoogia

Nagu majanumbrid tänaval, kui maja lammutatakse ja asemele ehitatakse uus, ei anta talle vana numbrit uuesti — pannakse "2A", et postiljon (vanad kliendid) ikka õigesse kohta jõuaks.

## Bootstrap Grid praktikas: container, row, col — `0:10:00` {#bootstrap-grid}

### Selgitus

LoginView'i paigutus ehitati Bootstrapi 12-veeruga grid-süsteemiga: `container` > `row justify-content-center` > `col col-3`. `justify-content-center` tsentreerib sisu rea (`row`) sees horisontaalselt, `col-3` annab veerule laiuse 3/12-st ekraani laiusest — sobiv kitsale login-vormile, mis ei tohi olla liiga lai.

Hiljem, kui vormi kohale lisati teavituskast (alert), tekkis vajadus **eraldi rida** (`row`) selle kasti jaoks, laiema veeruga (nt `col-6`), sest teavitussõnum võib olla pikem kui kitsas login-veerg.

### Koodinäide

Tegelik struktuur `LoginView.vue`-s:

```html
<div class="container text-center">
  <div class="row justify-content-center">
    <div class="col col-6">
      <!-- siia tuleb teavituskast (alert) -->
    </div>
  </div>

  <div class="row justify-content-center">
    <div class="col col-3">
      <h2>Sisse logimine</h2>
      <!-- siia tuleb vorm -->
    </div>
  </div>
</div>
```

### Päriselu analoogia

Kaks eraldi riiulit ühe kapi sees — ülemine riiul (`col-6`) on laiem, sest sinna käib suurem kast (teade), alumine riiul (`col-3`) on kitsam, sest sinna käib ainult väike vorm.

## Label ja input ilma id/for-ta — miks Vue's teisiti — `0:20:00` {#label-input}

### Selgitus

Varasemas puhtas HTML-i materjalis (vt [2026-08-25-video-2.md](2026-08-25-video-2.md)) õpiti, et `<label>` ja `<input>` seotakse kokku `for`/`id` atribuutidega. Vue's, kui kasutatakse `v-model`-it, ei ole seda enam vaja samal moel — `v-model` seob input otse andmemudeliga ning Bootstrapi `form-floating` klass hoolitseb visuaalse sildistuse eest ilma käsitsi id-sid kirjutamata.

### Koodinäide

```html
<div class="form-floating mb-3">
  <input v-model="loginRequest.username" type="text" class="form-control" placeholder="" />
  <label>Kasutajanimi</label>
</div>
```

**Tähelepanek:** `placeholder=""` on tühi, aga peab olema olemas, sest Bootstrapi `form-floating` CSS-trikk vajab seda toimimiseks.

## `methods` plokk ja `@click` sidumine — `0:35:00` {#methods-click}

### Selgitus

Loodi `methods` plokk komponendis ja sinna `login()` meetod. Nupule lisati `@click="login"`, mis on lühend `v-on:click="login"` jaoks — kui nupule vajutatakse, käivitub `login()` meetod.

### Koodinäide

```html
<button @click="login" type="submit" class="btn btn-primary">Logi sisse</button>
```

```javascript
methods: {
  login() {
    // siia tuleb loogika, mis käivitub nupule vajutades
  },
},
```

### Bootstrapi margin/padding utiliit-klassid

Samal ajal räägiti läbi Bootstrapi kiirklassid ruumi jaoks: `mt-` (margin-top), `mb-` (margin-bottom), `ms-` (margin-start ehk vasak), `me-` (margin-end ehk parem). Otsustati kasutada läbivalt `mb-3` (margin-bottom) elementide vahel, selle asemel et segamini kasutada `mt-` ja `mb-` — nii on koodis ühtlasem loogika ("iga element toob oma ruumi enda *alla*, mitte segamini üles ja alla").

See padding/margin teema kattub varem loodud materjaliga [css-padding-margin.md](../theory-materials/css-padding-margin.md) — õpetaja demonstreeris tunnis otse Claude Code'i abil sama materjali genereerimist, mis oli juba varem selles kursuses valmis tehtud.

## Andmevoog "ülevalt alla" ja miks React nii nimetati — `0:50:00` {#andmevoog}

### Selgitus

Vue (ja React) töötavad põhimõttel: **andmed voolavad ülevalt alla** (parent → child), aga **sündmused mullitavad alt üles** (child → parent). See tähendab, et lapskomponent ei tohi otse muuta vanema andmeid — ta saab ainult "anda märku" (event), et midagi juhtus, ning vanem otsustab, mida sellega teha.

**Miks "React"?** Facebook lõi React'i, sest vanal moel (jQuery-stiilis) pidi programmeerija ise käsitsi DOM-i uuendama iga kord, kui andmed muutusid — see läks keeruliseks, kui lehel oli palju dünaamilist sisu (nt lõputu kerimisega uudisvoog). React "reageerib" (*reacts*) andmete muutumisele automaatselt ja uuendab ekraani ise, ilma et programmeerija peaks käsitsi `document.getElementById()` tüüpi koodi kirjutama.

### Skeem

```
        Andmed (data)
Parent ───────────────▶ Child
   ▲                      │
   │                      │
   └──────────────────────┘
        Sündmused (events)
```

### Päriselu analoogia

Nagu firma juhtkonna ja töötaja suhe: juhtkond annab töötajale info (andmed voolavad alla), aga töötaja ei muuda ise juhtkonna otsuseid — ta saab ainult tõsta käe ja öelda "probleem on!" (sündmus mullitab üles), misjärel juhtkond otsustab, mida teha.

## `data()` funktsioon ja `v-model` kahesuunaline sidumine — `1:05:00` {#data-vmodel}

### Selgitus

Vue komponendi `data()` funktsioon tagastab objekti, kus on kirjas kõik komponendi enda muutuvad väärtused (state). `v-model` seob `<input>` välja otse mõne sellise väärtusega **kahesuunaliselt**: kui kasutaja tipib väljale, uueneb muutuja; kui muutujat koodis muudetakse, uueneb ka väljal näidatav tekst.

### Koodinäide

```javascript
data() {
  return {
    username: '',
    password: '',
  }
}
```

```html
<input v-model="username" type="text" />
```

## Vue DevTools: reaktiivsuse jälgimine — `1:15:00` {#devtools}

### Selgitus

Brauseri laiendus **Vue DevTools** näitab reaalajas komponendi `data()` sisu. Kui kasutaja tipib input-väljale, on DevTools'is otse näha, kuidas vastav muutuja väärtus muutub — see teeb `v-model`-i "nähtamatu maagia" käegakatsutavaks ja aitab silumisel (debugging) väga palju.

### Päriselu analoogia

Nagu läbipaistev kell, kus näed hammasrattaid liikumas — tavaline kell (ilma DevTools'ita) näitab ainult tulemust (kellaaega), aga läbipaistev kell näitab, mis mehhanismi sees tegelikult toimub.

## `this` võtmesõna: miks meetodis vaja, template'is mitte — `1:30:00` {#this-votmesona}

### Selgitus

Vue komponendis on kaks konteksti:

1. **`template` plokk** (HTML) — seal ei ole kunagi nimekonflikti, seega kirjutatakse lihtsalt `username`, mitte `this.username`.
2. **`methods`/`script` plokk** (JavaScript) — seal võib olla samanimeline lokaalne muutuja või parameeter, seega tuleb `this.username` abil täpsustada, et mõeldakse **just komponendi enda** `username`-t, mitte mõnda muud samanimelist muutujat lähedal.

See paralleelub Java setterite/getteritega: kui setter-meetodi parameetri nimi on sama, mis klassi väli (nt `public void setUsername(String username)`), tuleb `this.username = username` abil eristada, kumb `username` on klassi oma ja kumb parameeter.

### Koodinäide

```javascript
methods: {
  login() {
    // this.username viitab data() poolt tagastatud objekti username väljale
    if (this.loginRequest.username === '') {
      alert('Täida kõik välja')
    }
  },
},
```

```html
<!-- template's ei ole "this." vaja -->
<input v-model="loginRequest.username" />
```

## Pesastatud objekt: `loginRequest` ja `v-model="loginRequest.username"` — `1:45:00` {#pesastatud-objekt}

### Selgitus

Kahe eraldi muutuja (`username`, `password`) asemel otsustati need koondada **üheks objektiks** nimega `loginRequest`. See on kasulik, sest backendile saadetakse hiljem täpselt selline objekt tervikuna (vt API lepingu teemat eelmises materjalis) — nii on kood juba valmis kujul, mis vastab API-lt oodatavale struktuurile.

Pesastatud (nested) objekti väljale viitamiseks kasutatakse `v-model`-is punktnotatsiooni: `loginRequest.username`.

### Skeem

```
data()
 └── loginRequest (objekt)
      ├── username: ''
      └── password: ''
```

### Koodinäide

Tegelik kood `LoginView.vue`-s:

```javascript
data() {
  return {
    message: 'Täida kõik välja',
    loginRequest: {
      username: '',
      password: '',
    },
  }
}
```

```html
<input v-model="loginRequest.username" type="text" class="form-control" placeholder="" />
<input v-model="loginRequest.password" type="password" class="form-control" placeholder="" />
```

### Päriselu analoogia

Nagu postipakk, millel on üks pakikleebis (`loginRequest`), aga kleebi sees on mitu välja täidetud (saaja nimi, aadress) — selle asemel, et saata iga infokillu jaoks eraldi pakk.

## Väljade valideerimine: AND/OR kordamine if-lauses — `2:19:52` {#valideerimine}

### Selgitus

Ülesanne: kui **kumbki** väli (kasutajanimi või parool) on tühi, tuleb näidata veateadet. Loogika: "kui `username` on tühi **VÕI** `password` on tühi, siis viga."

Siin tuli mängu OR (`||`) lühisulgemine (short-circuit): kui esimene pool on juba tõene, ei kontrollita enam teist poolt — pole mõtet, sest tulemus on niikuinii "tõene".

### Koodinäide

Tegelik kood `LoginView.vue`-s:

```javascript
login() {
  if (this.loginRequest.username === '' || this.loginRequest.password === '') {
    alert('Täida kõik välja')
  }
},
```

### Levinud viga: `=` vs `===`

Tunnis tehti läbi tüüpiline algaja viga — kirjutati kogemata `=` (omistamine, "anna uus väärtus") selle asemel, et kirjutada `===` (võrdlus, "kas need on võrdsed"). Õpetaja selgitas vahet nii: `=` puudutab silti ja annab talle uue väärtuse, `===` võrdleb, ilma midagi muutmata.

### Päriselu analoogia

`=` on nagu nimesildi ümbertõstmine teisele inimesele ("nüüd oled sina Jaan"), `===` on nagu küsimus "kas sina oled Jaan?" — üks muudab, teine ainult kontrollib.

## Tingimuslik kuvamine: `v-if` teade kasutajale — `2:38:16` {#v-if-teade}

### Selgitus

Kuni siia hetkeni valiti ainult `alert(...)` (brauseri hüpikaken), mis on lihtne, aga kohmakas kasutajakogemus. Järgmine samm oli asendada see **Bootstrapi visuaalse teavituskastiga** (`alert alert-danger`), mida kuvatakse ainult siis, kui midagi on valesti — kasutades `v-if`.

`v-if="true"` näitab elementi alati (praegu ajutine, testimiseks kõva koodi sees); `v-if="false"` peidab elemendi täielikult (mitte ainult visuaalselt, vaid see eemaldatakse DOM-ist). Eesmärk on hiljem siduda see tingimus muutujaga, mis muutub `login()` meetodi sees.

Sõnumi tekst ise (nt "Täida kõik välja") toodi `data()` alt muutujasse `message`, ja `template`-is kuvati `{{ message }}` abil — nii saab hiljem sõnumi sisu meetodist muuta, ilma template'i puutumata.

### Koodinäide

Tegelik kood `LoginView.vue`-s (tunni lõpuseisuga, veel pooleli):

```html
<div v-if="true" class="alert alert-danger" role="alert">{{ message }}</div>
```

```javascript
data() {
  return {
    message: 'Täida kõik välja',
    // ...
  }
}
```

**Järgmiseks (homseks jäi pooleli):** siduda `v-if` tingimus tegeliku muutujaga (nt `showAlert`), mis lülitub sisse/välja `login()` meetodi sees vastavalt sellele, kas väljad on täidetud — ning hiljem tõsta see kast eraldi komponendiks (`AlertMessage`, `props: ['message']`), et sama teavituskasti saaks korduvkasutada mujal.

### Päriselu analoogia

Nagu suitsuandur, mis on kogu aeg seina peal olemas (element on template'is olemas), aga alarm kostub ainult siis, kui suitsu tegelikult on (`v-if` tingimus on tõene) — muidu on ta vaikselt "peidus", justkui teda polekski.
