## Pärilus — sissejuhatus — `0:01:07` {#parilus-sissejuhatus}

### Selgitus

**Pärilus (inheritance)** on omadus, mille abil üks klass võib **pärida** teise klassi väljad ja meetodid. See tähendab, et lapsklass (child) saab automaatselt kõik oma vanemklassi (parent) omadused, ilma et peaks neid uuesti kirjutama.

Sama põhimõte esineb ka frontendis — kuigi Vue's ei kasutata täpselt sama mehhanismi (klasside pärilust), on idee sarnane: taaskasutus, mitte kordamine.

### Skeem

```
      Vanemklass (parent)
      ┌────────────────┐
      │ väljad          │
      │ meetodid        │
      └────────────────┘
              ▲
              │ pärib
      ┌────────────────┐
      │ Lapsklass (child)│
      │ + oma väljad     │
      │ + oma meetodid   │
      └────────────────┘
```

### Päriselu analoogia

Pärilus on nagu see, kui laps pärib vanemalt teatud omadused (nt silmavärvi) — aga saab lisaks omandada ka oma isikupäraseid tunnuseid, mida vanemal ei ole.

## Setter meetodi struktuur ja nimereegel — `0:05:26` {#setter-meetodi-struktuur-ja-nimereegel}

### Selgitus

**Setter** on meetod, mis võimaldab **muuta** privaatse välja väärtust väljaspoolt klassi (kuna otse `objekt.väli = uusVäärtus` ei tööta, kui väli on `private`).

Meetodi struktuur on alati samas järjekorras:

```
nähtavus   tagastatav tüüp   nimi              parameetrid
  ▼             ▼              ▼                    ▼
public         void        setFirstName    (String firstName)
{
    this.firstName = firstName;
}
```

- **Nähtavus** — `public`, et meetod oleks väljaspoolt kutsutav.
- **Tagastatav tüüp** — setter ei tagasta midagi, seega `void`.
- **Nimi** — meetodi nimi peab sisaldama **tegusõna** (nt "set", "get", "handle") — üksnes `firstName` ei ütle, mida meetod teeb.
- **Parameeter** — väärtus, mis peab objekti väljale jõudma.

### Koodinäide

```java
public class Student {
    private String firstName;

    public void setFirstName(String firstName) {
        this.firstName = firstName; // this.firstName = objekti väli, firstName (parem pool) = parameeter
    }
}
```

### Kasutus

```java
Student student = new Student();
student.setFirstName("Peeter"); // objekti sisemine firstName saab väärtuse "Peeter"
```

### Oluline reegel

> **Meetodi ei tea oma välisest elust "ööd ega mütsi"** — meetod ei saa kuskilt maagiliselt teada väärtusi, mida talle ei antud. Kui meetod vajab andmeid väljastpoolt, peab olema **parameeter**, mille kaudu andmed sisse tuuakse.

## Parameetrid — analoogia Vue props'iga — `0:12:19` {#parameetrid-analoogia-vue-propsiga}

### Selgitus

Täpselt samamoodi, nagu Vue komponent ei tea, mis andmeid ta kuvama peab, kui talle ei anta **props'e**, ei tea Java meetod midagi väljastpoolt tema enda koodiplokki — kõik vajalik peab tulema **parameetrite** kaudu.

### Koodinäide (`frontend/src/components/location/NumberOfAtmsInput.vue`)

```vue
<script>
export default {
  props: {
    numberOfAtms: Number, // See on "parameeter", mida komponent väljastpoolt ootab
  },
  emits: ['event-new-number-of-atms-input'],
}
</script>
```

Komponent `NumberOfAtmsInput` ei tea iseenesest, mitu pangaautomaati kuvada tuleb — see teadmine tuleb sisse **props'ina**, täpselt nagu Java meetod saab andmeid **parameetrite** kaudu.

### Skeem

```
Vue komponent:                    Java meetod:
  props: { numberOfAtms }    ~     setFirstName(String firstName)
       ▲                                  ▲
       │  väärtus tuleb                   │  väärtus tuleb
       │  väljastpoolt                    │  väljastpoolt
  <NumberOfAtmsInput           student.setFirstName("Peeter")
    :numberOfAtms="5" />
```

### Päriselu analoogia

Parameeter on nagu tellimisvorm restoranis: kelner (meetod) ei tea, mida sa tahad söögiks, kuni sa (väljakutsuja) ütled talle konkreetse tellimuse (argumendi).

## Konstruktorite ülekoormamine (overloading) — `0:28:03` {#konstruktorite-ulekoormamine}

### Selgitus

Java lubab klassil olla **mitu konstruktorit**, kui nende **meetodi signatuur** (parameetrite arv ja/või tüübid) on erinev. Süsteem otsustab, millist konstruktorit käivitada, **vastavalt sellele, milliseid ja mitu argumenti `new` väljakutsel kaasa antakse**.

### Koodinäide

```java
public class Student {
    private String firstName;
    private String lastName;
    private int age;

    public Student() { }                                    // ilma parameetriteta

    public Student(String firstName, String lastName) {      // kaks parameetrit
        this.firstName = firstName;
        this.lastName = lastName;
    }

    public Student(String firstName, String lastName, int age) { // kolm parameetrit
        this.firstName = firstName;
        this.lastName = lastName;
        this.age = age;
    }
}
```

```java
Student student1 = new Student();                    // käivitub 1. konstruktor
Student student2 = new Student("Rain", "Tamm");       // käivitub 2. konstruktor
Student student3 = new Student("Peeter", "Paan", 42); // käivitub 3. konstruktor
```

### Oluline reegel

> Kohe kui kirjutad klassile **ühe** konstruktori käsitsi, kaob kompilaatori automaatne vaikekonstruktor. Kui tahad, et `new Student()` (ilma parameetriteta) ikka töötaks, pead selle konstruktori **eraldi ise kirjutama**.

### Päriselu analoogia

Konstruktorite ülekoormamine on nagu erinevad tellimisvõimalused kohvikus: "kohv" (ilma lisanditeta), "kohv piimaga" või "kohv piimaga ja suhkruga" — sina valid variandi vastavalt sellele, mida "koostisosi" kaasa annad, ja kohvik (konstruktor) teab automaatselt, millist retsepti järgida.

## NullPointerException — kui objekt on null — `0:33:13` {#nullpointerexception}

### Selgitus

Kui objekti väljale (nt `Integer age`) ei anta väärtust, on selle vaikeväärtus **`null`** — mitte "null number", vaid "täielik puudumine". Kui üritad `null` väärtust võrrelda (nt `<` või `>`), viskab Java **`NullPointerException`**.

### Koodinäide

```java
Student student1 = new Student("Rain", "Tamm", 42);
Student student2 = new Student("Peeter", "Paan"); // vanust ei antud — age on null

if (student1.getAge() < student2.getAge()) { // NullPointerException!
    // ...
}
```

`student2.getAge()` tagastab `null`, ja Java'l ei ole võimalik võrrelda "mitte midagi" mingi numbriga — pole ju õige öelda, et "mitte midagi" on suurem või väiksem kui 42.

### Päriselu analoogia

Vanuse võrdlemine `null`-iga on nagu küsimus "kas tühjus on vanem või noorem kui 42?" — küsimusel puudub mõte, kuna võrreldav asi puudub üldse.

## Oma meetodi kirjutamine: getFullName() — `0:36:32` {#oma-meetodi-kirjutamine-getfullname}

### Selgitus

Lisaks standardsetele getteritele/setteritele on täiesti tavaline kirjutada klassile **omaenda loogikaga meetodeid**, mis andmetega midagi ära teevad. Selline meetod ei ole "vaikimisi genereeritud" muster, vaid arendaja poolt kirjutatud äriloogika.

### Koodinäide

```java
public class Student {
    private String firstName;
    private String lastName;

    public String getFullName() {
        return firstName + " " + lastName; // "Juku" + " " + "Juhan" → "Juku Juhan"
    }
}
```

```java
Student student = new Student("Juku", "Juhan", 50);
System.out.println(student.getFullName()); // "Juku Juhan"
```

### Oluline

Meetodi sees on kättesaadavad **kõik objekti väljad** (isegi need, mis on `private`) — piirang kehtib ainult **väljaspoolsele** ligipääsule (`student.firstName` ei töötaks), aga klassi sisemuses (nagu selles meetodis) on igale väljale otsene ligipääs.

## Lombok — vähem koodi, samad meetodid — `0:44:18` {#lombok-vahem-koodi-samad-meetodid}

### Selgitus

Getterite, setterite ja konstruktorite käsitsi kirjutamine on korrektne, aga tüütu ja "risustab" koodifaili. **Lombok** on teek (library), mis genereerib need meetodid **automaatselt kompileerimise ajal**, kasutades annotatsioone.

### Levinumad Lombok annotatsioonid

| Annotatsioon | Genereerib |
|---|---|
| `@Getter` | kõikidele väljadele getterid |
| `@Setter` | kõikidele väljadele setterid |
| `@NoArgsConstructor` | tühi konstruktor (ilma parameetriteta) |
| `@AllArgsConstructor` | konstruktor, mis võtab sisse kõik väljad |
| `@Data` | kõike ülalolevat + `toString()`, `equals()`, `hashCode()` korraga |

### Koodinäide (`backend/src/main/java/ee/bcs/bank/infrastructure/error/ApiError.java`)

```java
package ee.bcs.bank.infrastructure.error;

import lombok.Data;

@Data
public class ApiError {
    private String message;
    private String errorCode;
}
```

See lühike klass saab `@Data` annotatsiooni abil **automaatselt** kõik getterid, setterid, `toString()`, `equals()` ja `hashCode()` meetodid — ilma, et neid oleks vaja käsitsi kirjutada.

### Koodinäide: Lombok koos käsitsi kirjutatud konstruktoriga (`backend/src/main/java/ee/bcs/bank/infrastructure/exception/DataNotFoundException.java`)

```java
package ee.bcs.bank.infrastructure.exception;

import lombok.Getter;

@Getter
public class DataNotFoundException extends RuntimeException {
    private final String message;
    private final String errorCode;

    public DataNotFoundException(String message, String errorCode) {
        super(message);
        this.message = message;
        this.errorCode = errorCode;
    }
}
```

Siin on korraga näha **kaks** selle video teemat:
- `@Getter` annotatsioon genereerib `getMessage()` ja `getErrorCode()`.
- `extends RuntimeException` — see klass **pärib** Java standardteegi `RuntimeException` klassilt (pärilus praktikas).

### Skeem: bytecode näitab genereeritud meetodeid

```
Kirjutatud kood (.java)          Kompileeritud kood (.class)
┌─────────────────────┐          ┌───────────────────────────┐
│ @Getter              │   →      │ private String message;    │
│ private String       │          │ private String errorCode;  │
│   message;            │          │                             │
│ private String        │          │ public String getMessage() │
│   errorCode;          │          │ public String getErrorCode()│
└─────────────────────┘          └───────────────────────────┘
        (nähtav failis)              (nähtav vaid bytecode's/
                                       decompiled .class failis)
```

### Väike huvitav fakt

Programmeerimiskeele **Java** nimi tuleb Indoneesia saarelt **Jaava (Java)** — sõna eksisteeris juba enne keele loomist. Levinud kohvi/saare teemaline sümboolika (nt Lomboki teegi ikoon) on selle nimega seotud sõnamäng.

## Pärilus praktikas: extends — `0:52:12` {#parilus-praktikas-extends}

### Selgitus

Java's kirjeldatakse pärilussuhet võtmesõnaga **`extends`**. Kui klass `B` laiendab klassi `A` (`class B extends A`), saab `B` automaatselt kõik `A` väljad ja meetodid — ja võib lisaks defineerida oma täiendavaid välju/meetodeid.

### Koodinäide

```java
public class Student {
    private String firstName;
    private String lastName;
    private int age;
}

public class HighSchoolStudent extends Student {
    private double averageGrade; // lisaväli, mida on ainult keskkooliõpilasel
}
```

```java
HighSchoolStudent highSchoolStudent = new HighSchoolStudent();
// highSchoolStudent objektis on olemas KÕIK Studenti väljad + averageGrade
```

### Skeem

```
       Student (parent/vanemklass)
       ┌───────────────────┐
       │ firstName          │
       │ lastName            │
       │ age                  │
       └───────────────────┘
                 ▲
                 │ extends
       ┌───────────────────┐
       │ HighSchoolStudent   │
       │ (child/lapsklass)   │
       │ + averageGrade      │
       └───────────────────┘
```

### Oluline nüanss: konstruktorid ei tule pärimisel kaasa automaatselt

Kui `HighSchoolStudent`-il ei ole enda konstruktorit, kasutab ta vaikimisi kompilaatori loodud tühja konstruktorit. Kui `Student`-il on aga defineeritud **ainult** konstruktor(id) parameetritega (nt kõiki kolme välja võttev), ei ole `HighSchoolStudent`-il enam automaatset ligipääsu Studenti väljade otsesele väärtustamisele, kui ta ise vastavat konstruktorit ei defineeri — vajalik on eraldi konstruktor ka lapsklassis.

### Päriselu analoogia

`HighSchoolStudent` on nagu spetsialiseeritud versioon `Student`-ist — samamoodi nagu "sportauto" on ikkagi "auto" (kõik auto omadused säilivad), aga sellel on lisaks mõned eriomadused (nt suurem mootorivõimsus), mida tavalisel autol ei ole.

## Kõik klassid pärinevad Object klassist — `0:59:34` {#koik-klassid-parinevad-object-klassist}

### Selgitus

Java's **iga** klass, mille sa lood, pärib automaatselt (isegi kui sa seda otseselt kirja ei pane) klassist **`Object`**. Seda ei ole vaja eraldi kirjutada (`class Student extends Object` on iseenesest mõistetav ja tehniliselt ülearune).

`Object` klass pakub baasmeetodeid, mis on olemas **absoluutselt igal** Java objektil:

- `toString()` — objekti tekstilise esituse tagastamine
- `equals(Object o)` — objektide sisu võrdlemine
- `hashCode()` — objekti "räsiväärtus" (kasutatakse nt Map'ides ja Set'ides)
- `getClass()` — objekti klassi info
- `wait()`, `notify()` — lõimede (threads) sünkroniseerimiseks

### Skeem

```
                 Object (Java standardklass)
                 ┌───────────────────────┐
                 │ toString()             │
                 │ equals()               │
                 │ hashCode()             │
                 │ getClass()             │
                 └───────────────────────┘
                           ▲
                           │ (kõik klassid pärivad seda automaatselt)
                 ┌───────────────────────┐
                 │ Student                │
                 └───────────────────────┘
```

### Päriselu analoogia

`Object` klass on nagu "üldine inimõiguste dokument" — kõik objektid (nagu kõik inimesed) omavad automaatselt teatud baasõigusi/-omadusi, ilma et neid iga korra eraldi peaks väljastama.

## toString() meetod ja @Override — `1:06:03` {#tostring-meetod-ja-override}

### Selgitus

Kui prindid objekti otse konsooli (nt `System.out.println(student)`), kutsub Java taustal automaatselt välja meetodi **`toString()`**. Vaikimisi (kui seda ise üle ei kirjuta) tagastab see midagi arusaamatut, nagu paki-aadress + hex-kood (`ee.bcs.bank.Student@2f4d3709`).

Selle vältimiseks **kirjutatakse `toString()` üle** (override), et see tagastaks midagi loetavat.

### Koodinäide

```java
public class Student {
    private String firstName;
    private String lastName;
    private int age;

    @Override
    public String toString() {
        return "Student(age=" + age + ", firstName=" + firstName + ")";
    }
}
```

`@Override` annotatsioon ei ole kohustuslik, aga on hea tava — see annab kompilaatorile ja teistele arendajatele märku, et see meetod **teadlikult üle kirjutab** vanemklassi (`Object`) versiooni.

### Skeem

```
System.out.println(student)
         │
         ▼
Java kutsub taustal: student.toString()
         │
         ├── kui toString() on üle kirjutatud → kasutab SEDA versiooni
         └── kui ei ole → kasutab Object klassi vaikimisi versiooni (hex-kood)
```

### Päriselu analoogia

`toString()` on nagu visiitkaart — vaikimisi versioon annab vaid tehnilise "seerianumbri", aga oma kujundatud versiooniga saad selle asemel näidata midagi mõistetavat, nt "Rain Tamm, 42".

## equals() ja hashCode() meetodid — `1:12:05` {#equals-ja-hashcode-meetodid}

### Selgitus

Vaikimisi `equals()` meetod (mis tuleb `Object` klassist) võrdleb objekte **mäluviite** järgi — see tähendab, et kaks eri objekti, mille sisu on identne, loetakse `equals()`-iga **erinevaks**, kui need ei ole täpselt üks-ja-seesama objekt mälus.

```java
Student student1 = new Student("Rain", "Tamm", 42);
Student student2 = new Student("Rain", "Tamm", 42);

student1.equals(student2); // false, kuna vaikimisi equals() vaatab mäluviidet, mitte sisu!
```

Kui soovid, et `equals()` võrdleks **sisu** (kõiki välju), tuleb see meetod **üle kirjutada** (nii nagu `toString()`).

### Koodinäide

```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (o == null || getClass() != o.getClass()) return false;
    Student student = (Student) o;
    return age == student.age &&
           Objects.equals(firstName, student.firstName) &&
           Objects.equals(lastName, student.lastName);
}

@Override
public int hashCode() {
    return Objects.hash(firstName, lastName, age);
}
```

### Reegel

> `equals()` ja `hashCode()` kirjutatakse **alati koos üle** — need käivad käsikäes (kui objektid loetakse `equals()`-iga võrdseks, peab neil olema ka sama `hashCode()`).

### Lombok lahendus

Käsitsi kirjutamise asemel saab kasutada Lombok annotatsiooni `@Data` (või `@EqualsAndHashCode`), mis genereerib nii `equals()` kui `hashCode()` korraga, arvestades kõiki klassi välju.

### Päriselu analoogia

Vaikimisi `equals()` on nagu kahe eraldi trükitud raamatuvõõra eksemplari võrdlemine "on need täpselt üks ja seesama füüsiline raamat käes?" — üle kirjutatud `equals()` küsib hoopis "on nende **sisu** identne?", mis on tavaliselt see, mida tegelikult tahame teada.

## Sõltuvuste allalaadimine — kordamine — `1:18:32` {#soltuvuste-allalaadimine-kordamine}

### Selgitus

Lühike kordus eelmisest videost: kõik teegid (nagu Lombok ja Swagger), mida projektis kasutatakse, on defineeritud `build.gradle` faili `dependencies` blokis. Kui projekt esimest korda avatakse (või `build.gradle` muudetakse), tuleb Gradle'il ("elevant") lasta **refresh'ida** — see tõmbab kõik vajalikud teegid kesksest hoidlast (repositoriumist) alla.

### Koodinäide (`backend/build.gradle`)

```groovy
dependencies {
    // Lombok — annab meile @Data, @Getter, @Setter, @AllArgsConstructor jms
    compileOnly 'org.projectlombok:lombok'
    annotationProcessor 'org.projectlombok:lombok'

    // Swagger — API dokumentatsioon
    implementation 'org.springdoc:springdoc-openapi-starter-webmvc-ui:3.0.3'
}
```

Kui rida on `build.gradle` failist eemaldatud, kaovad ka vastavad võimalused (nt Lombok annotatsioonid ei toimi enam) — seetõttu on oluline mõista, et **kõik projekti "maagilised" võimalused tulevad kuskilt konkreetsest reast selles failis**.

Käsitleti, kuidas meetodid ja klassid "ei tea oma välisest elust ööd ega mütsi" ja vajavad andmete saamiseks parameetreid — täpselt samamoodi nagu Vue komponendid vajavad props'e. Suur osa videost kulus Lombok teegi tutvustamisele (`@Getter`, `@Setter`, `@Data`, `@AllArgsConstructor`, `@NoArgsConstructor`), mis vabastab arendaja korduva boilerplate-koodi kirjutamisest, ning `Object` klassi baasmeetodite (`toString()`, `equals()`, `hashCode()`) ülekirjutamisele. Praktilise näitena tutvustati pärilust `extends` võtmesõnaga (`HighSchoolStudent extends Student`).
