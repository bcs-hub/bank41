git · repositooriumi hooldus

Git prune:
prügikasti tühjendamine

Git ei kustuta iial midagi kohe. Iga kustutatud haru, iga rebase, iga commit --amend jätab endast maha commit'e, millele enam miski ei viita. git prune on käsk, mis need lõplikult minema pühib.

Prügikasti analoogia kustutamine peidab faili → prune tühjendab prügikasti päriselt

Enne ja pärast

Kui kustutad haru, ei kao selle commit'id kettalt — nad jäävad .git kausta sisse "kummitustena", kuni miski (või keegi) need koristab. Vajuta nuppu ja vaata, mis juhtub.

Commit-graaf

Hall haru on kustutatud, aga selle kolm commit'i jäävad kettale hüljatuna, kuni käivitad prune'i.

Miks see oluline on

.git kaust kasvab aja jooksul, sest Git säilitab vaikimisi kõik objektid — ka need, mida keegi enam ei kasuta:

  • Kustutatud harude commit'id
  • git rebase või git commit --amend käigus tekkinud vanad versioonid
  • git reset --hard käigus mahajäänud commit'id

Need objektid võtavad kettaruumi, kuigi neile enam miski ei viita. git prune hoiab repositooriumi puhtana.

Proovi ise (turvaliselt)

Enne päris kustutamist tasub alati vaadata, mida kustutataks — selleks on --dry-run lipp. Alloleval terminalil pole päris jõudu, aga selle käsud ja väljundid on tõesed.

bash — sandbox

Vali käsk allpool, et näha selle väljundit.

Ettevaatust git prune on pöördumatu. Kui kustutad objekti, mida oleks vaja läinud (nt taastamiseks git reflog abil), siis pärast prune'i see enam ei õnnestu. Tavalises igapäevatöös ei pea seda käsitsi käivitama — Git teeb sarnast tööd ise git gc kaudu.

Kolm sarnast, aga erinevat käsku

Neid aetakse tihti segi — igaühel on oma roll.

Käskude võrdlus
KäskMida teeb
git prune Kustutab lokaalsed hüljatud objektid (commit'id, blob'id) kettalt.
git gc Üldine "prügikoristus" — pakib objektid kokku, kutsub ka prune'i, aga arvestab reflog'i ja varutähtaegu.
git fetch --prune Eemaldab lokaalsed viited kaugharudele, mis serveris enam ei eksisteeri.
git branch -d Kustutab ühe lokaalse haru — commit'id ise jäävad kettale, kuni prune need koristab.
