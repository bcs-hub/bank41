HTTP sõnum: kiri brauseri ja serveri vahel

Iga kord, kui brauser laadib lehe või Vue rakendus küsib backendilt andmeid, saadetakse kokkuleppelise vormiga kiri. Klient saadab päringu, server vastab vastusega — mõlemal on sama ehitus.

Tähitud kirja analoogia päised = ümbrik · keha = kirja sisu

HTTP sõnumi ehitus

Nii päringul kui vastusel on kolm osa: algusrida, päised ja valikuline keha, mis on päistest eraldatud tühja reaga.

Algusrida
mida tahetakse / mis juhtus
Päised
Key: Value (lisainfo sõnumi kohta)
—
tühi rida eraldab päised kehast
Keha
tegelik andmesisu (valikuline)

Katsuta ise: pane päring kokku

Vali meetod ja vaata, kuidas HTTP päring reaalselt välja näeb — täpselt selline sõnum liigub brauserist serverisse, kui Vue rakendus teeb this.$axios päringu.

Päring (request)

POST-il ja PUT/PATCH-il on tavaliselt keha (JSON) — GET ja DELETE tavaliselt kehata, kuna nad ei saada andmeid kaasa.

Levinumad HTTP meetodid

Meetod ja tähendus
MeetodAnaloogiaKasutus
GET"Näita mulle"Andmete pärimine, ei muuda midagi
POST"Siin on uus asi"Uue ressursi loomine
PUT"Asenda see täielikult"Täielik uuendamine
PATCH"Muuda ainult see osa"Osaline uuendamine
DELETE"Kustuta see"Ressursi kustutamine

Katsuta ise: staatuskoodid

Vali staatuskood ja vaata, mis kategooriasse see kuulub. Esimene number ütleb kohe, kuidas läks: 2xx õnnestus, 4xx sinu (kliendi) viga, 5xx serveri viga.

Päised — lisainfo ümbrikul

Päised on võti-väärtus paarid, mis annavad sõnumi kohta lisainfot, ilma et need oleksid osa tegelikust sisust.

Levinumad päised
PäisKasutus
Content-TypeMillises formaadis on keha (nt application/json)
Content-LengthKeha pikkus baitides
AuthorizationAutentimisinfo (nt token)
AcceptMillises formaadis klient vastust soovib
Set-CookieServer palub kliendil salvestada küpsise
